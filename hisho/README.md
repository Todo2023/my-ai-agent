# 秘書・進捗管理

全事業を横断した**日次サマリー**を出すための道具。
役割定義は [`../CLAUDE_team.md`](../CLAUDE_team.md) の「秘書・進捗管理担当者」にある。

## 費用はゼロ

**この仕組みでかかる費用はありません。**

| 使うもの | 費用 | カード登録 |
| --- | --- | --- |
| Python 3（標準ライブラリのみ） | 0円。端末にあるものを使う | 不要 |
| 外部への通信 | **しない** | — |
| Claude API / Gemini API | **使わない**。`items.json` を並べ替えて整形するだけ | — |

生成AIは使っていない。中身を書くのは人（または会話中のClaude Code）で、
このスクリプトは**書いたものを決まった形に並べ直すだけ**。

## 使い方

```bash
python3 hisho/daily.py                   # 全件（詳細版）
python3 hisho/daily.py --brief           # 1行ずつの短い版
python3 hisho/daily.py --state 判断待ち   # 状態でしぼる
python3 hisho/daily.py --business match  # 事業でしぼる
python3 hisho/daily.py --out today.md    # ファイルに書き出す
```

`--out` の書き出し先は**リポジトリに入れない**（日々の状態はコミットせず、
`items.json` のほうを直す）。

## 中身の直し方

状態が変わったら [`items.json`](items.json) を手で書き換える。
1件はこの形。

```json
{
  "id": "match-01",
  "business": "match",
  "title": "登録フォームと管理画面がどこにもつながっていない",
  "state": "止まっている",
  "background": "なぜこのタスクが発生しているか",
  "evidence": "なぜ今のステータスなのか。何が判断・進行を止めているか",
  "next_action": "次に何をすれば動くか",
  "owner": "代表",
  "source": "TODO.md / hp/match/README.md"
}
```

役割定義書が求めている「1件あたり詳細版（背景・根拠・次アクション）」が、
`background` / `evidence` / `next_action` にそのまま対応する。

| 欄 | 何を書くか |
| --- | --- |
| `state` | `判断待ち` `止まっている` `手つかず` `進行中` `順調` `完了` の6つだけ |
| `owner` | `代表` か `支援チーム`。どちらの手が要るか |
| `source` | **その話がどこに書いてあるか**。ここが空の項目は書かない |

`source` を必須にしているのは、**思い込みで項目を増やさないため**。
リポジトリや会議記録に根拠が無い話は、一覧に入れずに口頭で相談する。

## 並び順

手が要るものが上に来るようにしてある。

`判断待ち` → `止まっている` → `手つかず` → `進行中` → `順調` → `完了`

同じ状態の中は、役割定義書の優先度①〜⑥の順。
**事業ごとのセクションには分けない**（役割定義書がそう決めている）。
`順調` な件も一覧から省かない。

## 決まりごと

- **自動実行・定期実行は作らない。** 見たいときに手で走らせる
- 書き換えたら `python3 hisho/daily.py` を1回通す。
  知らない `state` や `business` が混ざっていればその場で止まる
- 完了した項目は、しばらく `完了` のまま残してから消す
  （何が終わったかが日次の一覧から消えると、進んだ実感が残らないため）
