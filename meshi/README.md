# スクショ飯

行きたい店のスクショを撮っておくと、それがそのまま「行きたいリスト」になる。
行ったら写真の **✓** を押すだけで「行った店」の記録に移る。

スマホに入れられる PWA（Android / iPhone どちら も可）。サーバーも外部APIも使っていない。
**貯まったデータはその端末のブラウザの中だけ**にあり、どこにも送信していない。

```
# ローカルで動かす（Service Worker を使うので http で開く）
python3 -m http.server 8000 --directory meshi
# → http://localhost:8000
```

## 使い方

1. 気になる店を見つけたら**スクショを撮る**（食べログ・Instagram・地図・友達のLINE、何でもいい）
2. アプリの「**スクショを取り込む**」で写真から選ぶ
3. 行ったら写真の右上の **✓** を押す。「行った」タブに日付つきで移る

店名やメモは**後から入れればいい**。写真を見れば思い出せるので、入れなくても機能する。
「名前をつける」のまま貯めておいて、行く直前に埋めるのが実際の使い方になる。

## スクショが勝手に貯まる仕組み

入口は2つある。どちらも入ってくる先は同じ。

| 端末 | やり方 |
| --- | --- |
| **Android** | 写真やブラウザの**共有**メニューから「スクショ飯」を選ぶ。それだけで1軒増える |
| **iPhone / どの端末でも** | アプリの「スクショを取り込む」→ 写真アプリの**スクリーンショット**アルバムから全部選ぶ |

肝は**取り込み済みのスクショを弾く**こと（画像の中身から SHA-256 の指紋をとって照合する）。
だから毎回「全部選ぶ」で構わない。新しく撮ったぶんだけが足され、同じ写真が二重に並ぶことはない。
**選び方を覚えなくていい**——毎回まったく同じ操作でよくなる、というのがこの仕組みの狙い。

iPhone の共有メニューにこのアプリは出せない（iOS が Web Share Target に対応していないため）。
iPhone では上の「全部選ぶ」が定位置の操作になる。

Android の共有では**リンクも受け取れる**。食べログや地図のページを共有すると、
リンク付きで1軒でき、詳細から「🔗 リンクを開く」でそのまま戻れる。

## できること

| | |
| --- | --- |
| 行きたい / 行った | 2つのタブ。数はタブに出る |
| ✓ | 一覧から1タップで「行った」へ。押し間違えても**取り消せる**（6秒だけ出る「取り消す」） |
| 行った日・評価 | 「行った」に移すとその日の日付が入る。★5段階（同じ星をもう一度押すと取り消し） |
| 店名・メモ・タグ | 詳細画面で。入力は打つそばから保存される |
| タグで絞る | タグは一覧の上にチップで出る。よく使う順。複数選ぶと絞り込みが重なる |
| さがす | 店名・メモ・タグ・リンクをまとめて検索 |
| 🗺 地図で開く | 店名（＋タグ）で Google マップを検索する。ここから経路に繋がる |
| スクショを足す | 1軒に複数枚。外観・メニュー・地図を1軒にまとめられる |
| 書き出し / 読み込み | JSON。画像ごとと、文字だけの軽い方を選べる。機種変更のときはこれで移す |
| オフライン | 圏外でも起動して全部見られる（通信するのは地図とリンクを開くときだけ） |

## スマホに入れる

**https://todo2023.github.io/my-ai-agent/meshi/** を開くと、まずインストール画面が出る。

- **Android（Chrome）**: 「📲 アプリとして入れる」ボタンをタップ
- **iPhone（Safari）**: 画面の案内どおり、共有 → 「ホーム画面に追加」

ホーム画面のアイコンから起動したときは、この画面を挟まず `app.html` へ転送する
（manifest の `start_url` も `app.html`）。**共有メニューに出るのはインストールした後**。

`qr.png` はこの URL のQRコード。カメラで読めばURLを打たずに開ける。

### うまく開けない・入らないとき

**`meshi/` を最後まで付けた URL であること**を先に確認する。
`https://todo2023.github.io/my-ai-agent/` だけだと**別のアプリ（ブロック崩し）**が出る。

それでも駄目なら **[check.html](./check.html)** を開く。
どのService Workerが担当しているか・保存が使えるか・インストールできる状態かが一覧で出る。
画面を撮って渡せば原因が分かる。「キャッシュを消して読み直す」ボタンもここにある。

## ファイル

| | |
| --- | --- |
| `index.html` | インストール案内画面。QRやURLはここに着く |
| `app.html` | アプリ本体の画面 |
| `check.html` | インストール診断。開けない・入らないときに見る |
| `qr.png` | 公開URLのQRコード |
| `app.css` / `app.js` | 見た目と中身 |
| `db.js` | IndexedDB のスキーマ。本体と Service Worker の両方から読む |
| `manifest.webmanifest` | インストール設定と `share_target`（共有メニューに出る設定） |
| `sw.js` | オフライン用キャッシュ＋**共有された画像の受け取り** |
| `icon-*.png` / `apple-touch-icon.png` | アイコン（`_icon.html` を Canvas で描いて書き出したもの） |
| `_icon.html` / `_build_icons.js` | アイコンの元絵と書き出し（`node meshi/_build_icons.js`） |

`app.css` などを直したら `sw.js` の `CACHE` の版数を上げること。上げないと古いまま開かれる。

## 実装メモ

- **スクショの重複判定は中身のハッシュ**。ファイル名や撮影日時ではない。同じ画像を撮り直しても
  違うものとして入るが、同じファイルは何度選んでも1件。`shots` の `hash` に unique 索引を張ってある
- **保存は3つに分けた**。`places`（文字）・`shots`（一覧用の縮小画像 640px）・`blobs`（元画像）。
  一覧を開くたびに元画像まで読むと端末が止まるので、**元画像は詳細を開いたときだけ**読む
- **共有シートは Service Worker でしか受けられない**。`share_target` の POST は普通のページには届かないので、
  `sw.js` が `formData` を開いて `inbox` に積み、アプリ側が起動時に引き取る（`drainInbox`）。
  開きっぱなしのときのために `postMessage` でも合図を送っている
- **同じサイトに同居する別アプリの Service Worker に注意**。リポジトリ直下のブロック崩しの
  `sw.js` は担当範囲が `/my-ai-agent/` なので、放っておくと `meshi/` のページまで横取りし、
  通信が細いときの navigate フォールバックで**ブロック崩しの画面を返してしまう**。
  直下の `sw.js` 側で `/meshi/` `/todo_game/` を除外し、こちら側でも
  「別アプリが担当していたら、自前のに替わった時点で1回だけ読み直す」（`healForeignController`）を入れてある
- **削除のあとに保存しない**。閉じるときに自動保存する作りなので、削除→閉じるの順だと
  消したはずの店が書き戻る。`hideDetail()`（保存しない）と `closeDetail()`（保存する）を分けてある
- **「行った」は取り消せる**。一覧の ✓ は指が当たりやすい位置にあり、誤操作を前提にした
- 画像の読み込みは `createImageBitmap` → 失敗したら `<img>` の順に試す（HEIC など端末依存のため）。
  縮小に失敗しても元画像は保存する。写真を取りこぼさないことを優先した
- 星は**同じ星をもう一度押すと0に戻る**。5段階しかないので、押し間違えたときの逃げ道がないと困る

## 次にやるなら

1. **スクショから店名を読む（OCR）** — いまは手入力。ここが自動になると「名前をつける」が消える
2. **地図にまとめて出す** — 「この辺で行きたい店」が出せると、外にいるときに効く
3. **行った店から次を選ぶ** — 「★4以上でまた行きたい店」の再訪リスト
4. **共有で書き出す** — 友達に「行った店リスト」を渡す
