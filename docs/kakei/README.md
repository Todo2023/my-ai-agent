# 家計のみらい

毎月の収支を入れると、**この先の残高が1本の線**になる。
「いまの暮らしのまま行くと、貯金はいつまでもつのか」だけを答える。

家計簿ではない。**記録は一切とらない**。毎日つけることを求めた時点で続かないし、
過去をいくら正確に記録しても、この先どうなるかは出てこない。

スマホに入れられる PWA（Android / iPhone どちらも可）。サーバーも外部APIも使っていない。
**入れた金額はその端末のブラウザの中だけ**にあり、どこにも送信していない。

```
# ローカルで動かす（Service Worker を使うので http で開く）
python3 -m http.server 8000 --directory kakei
# → http://localhost:8000

# 計算が合っているかを確かめる（ブラウザは要らない）
node kakei/_test.js
```

## 使い方

1. **合い言葉**を入れて、家計をひらく（初めての端末だけ。次からは聞かれない）
2. **収支** に、毎月の収入と支出を項目ごとに入れる（**円／月**・収入は**手取り**）
3. **前提** に、退職する年齢・退職金・年金・いまの貯蓄を入れる
4. あとはグラフを眺める。**尽きる年**と、**あと月いくら使えるか**が最初の一文に出る

## 合い言葉で封をしてある

このリポジトリは公開されている。だから**家族の名前も金額も、平文では置いていない**。
中身は [`preset.enc.json`](./preset.enc.json) に暗号文としてだけ入っていて、
合い言葉を入れたときに、端末の中で復号される。

```
合い言葉 --PBKDF2-SHA256（31万回）--> 鍵 --AES-256-GCM--> 中身
```

合い言葉も鍵もどこにも送らない（サーバーが無い）。置いてあるのは塩・IV・暗号文だけ。

- **打ち方は問わない。** ひらがな・カタカナ・半角カナ・ローマ字・大文字小文字・空白のゆれを
  ならしてから鍵を作る（`canon`）。スマホで日本語入力か英字入力かは、打つ人には制御しづらいため
- **いちど開いた端末では、次から聞かれない。** 復号した家計はその端末に保存される。
  つまり守っているのは**公開されているファイル**であって、端末そのものではない
- **封を作り直しても、開いた端末は自動では追いつかない**（毎回合い言葉を聞かない作りなので）。
  そこで封には日付の印（`stamp`）だけ平文で付けてあり、起動のたびに**印だけ**を見に行く。
  新しければ画面の上に帯が出る。読み込むと**その端末で直したものは置き換わる**ので、押すかどうかは本人が決める
- 合い言葉なしで開くと、**だれのものでもない見本の家計**が出る（`secret.js` の `SAMPLE`）
- 別の端末で開くときは、その端末で1回だけ合い言葉を入れる

### 中身を入れ替える・合い言葉を変える

アプリで直して書き出し、封をし直して commit する。

```bash
# 設定 →「⬇ 書き出す（JSON）」で作ったファイルから封をする
node kakei/_seal.js ~/Downloads/kakei-2026-08-11.json "あたらしい合い言葉"
# → kakei/preset.enc.json が作り直される
```

**元のJSONはリポジトリの中に置かないこと。** 置いたら封をした意味がなくなる。

### 家族と年齢

名前と生年月日は封の中にあり、入力欄は作っていない（変わらないものなので）。

**年齢は持たず、生年月日から出す。** 年齢を保存すると年をまたぐたびにずれて、
毎年入れ直すことになる。生年だけ持っていれば、いつ開いても正しい年齢で計算される。

グラフと表の年齢は**その年に迎える年齢**（西暦 − 生年）。「65歳で退職」は「65歳になる年に辞める」。
前提の画面だけは、誕生日を迎えたかどうかまで見た**今日ちょうどの年齢**を出している。
子どもとペットも前提の「家族」に並ぶ（いま何歳かがすぐ引ける）。

年に一度しか出ていかないもの（ふるさと納税・車検・帰省）は、**12で割った額**を入れる。
その月だけ谷を作っても、月々の収支が読めなくなるだけで、年で見れば同じになる。

### 貯蓄は「支出」に数えない

つみたても共済も、財布からは出ていくが**自分の資産として残る**。
支出に混ぜると「毎月ぜんぶ使い切っている」ように見えてしまう。

項目に **「貯める」** の印を付けると、出ていくお金から外れ、資産に積み上がる。
最初から入っている表では、つみたてと共済の3項目にこの印が付いている。

> 例：収入 50万 − 支出 27.9万 = 手元に残る現金 22.1万。
> このうち「貯める」が 5万あるなら、**毎月ふえる資産は 22.1万＋5万ではなく 22.1万** ——
> ではなく、支出から外したぶんを足し戻して考える。画面には両方が並べて出る。

### 項目ごとに決められること（**⌄** を押す）

| | |
| --- | --- |
| いつから / いつまで | 育休手当・養育費・学費のように**終わりがあるもの**を区切る。空欄ならずっと |
| だれの収入か | 名前を選んでおくと、**その人が仕事をやめた年に自動で止まる** |
| 昇給率 | その収入だけに効く（%/年） |
| 退職したら止まる | 通勤費・社宅利用料など、**仕事とセットで消える支出** |
| 物価とともに増える | 食費は上がるが保険料は上がらない。項目ごとに選べる |
| 貯める | 資産に残るお金（つみたて・共済） |

**終わりのある項目を放っておくと、一生続く計算になる。** ここがいちばん結果を動かす。

## できること

| | |
| --- | --- |
| 一文の答え | もつ／尽きる、あと月いくら減らせば（増やせば）いいか |
| お金の置き場 | いまの貯蓄・投資を**口座ごと**に。**いつ時点の残高か**を持つので、古くなると「3か月前」と出る |
| 毎月の収支 | 入る・出る・貯める・手元に残る現金。グループごとの小計つき |
| カードの引落 | カードごとに、月ごとの引落額を記録する（2026年8月分から）。月をめくって入れ、前の月との差も出る |
| グラフ | 年ごとの残高。指でなぞるとその年が読める。退職の年に縦線、尽きる年に赤い点 |
| 年ごとの表 | 押すと**その年の内訳**（給料・年金・教育費・ローン…）が出る |
| ライフイベント | 子どもの教育費（自動計算）・住宅購入（返済と維持費）・車や介護などの臨時 |
| プラン比較 | 複製して1か所だけ変え、**グラフに2本重ねる**。買う／買わない、早く辞める／続ける |
| 書き出し / 読み込み | JSON。機種変更のときはこれで移す |
| オフライン | 圏外でも起動して全部動く（そもそも通信しない） |

## 何をどう計算しているか

計算は [`sim.js`](./sim.js) にまとまっている。画面から切り離してあるので、
`node kakei/_test.js` で数字だけを確かめられる（45件の突き合わせが通る）。

- **スタート地点は口座の合計。** 1つも入れていなければ、手打ちの総額を使う（`accounts` が空のときだけ）
- **1年ずつ回す。** 前年までの資産に利回りをかけ、その年の収入と支出を足し引きする
- **資産がマイナスの年は利息を付けない。** 借金の利率まで見立てると「いくら借りるのか」という
  別の前提が要る。マイナスは金額ではなく**警告として見る**もの
- **年金は65歳から。** 物価スライドは見込まない（マクロ経済スライドで実質は目減りするので、少なめに置く）
- **退職後の生活費**は、前提の割合（既定 80%）を掛ける。はっきり止まるものは項目側の「退職したら止まる」で
- **住宅ローンは元利均等**。3500万・1.5%・35年 → 月10.7万（金融機関の返済額表と同じ）
- **維持費**は物件価格に対する割合（既定 1.2%/年）。固定資産税・管理費・修繕積立金・火災保険のぶん

### 教育費（子どもを足したときだけ）

文部科学省「子供の学習費調査」（学校教育費＋給食費＋学校外活動費）と、大学の授業料・入学金のめやす。

| | 1年あたり |
| --- | --- |
| 0〜2歳（保育園） | 30万 |
| 3〜5歳 | 公立 17／私立 31 万 |
| 小学校 | 公立 35／私立 167 万 |
| 中学校 | 公立 54／私立 144 万 |
| 高校 | 公立 51／私立 105 万 |
| 大学 | 国公立 60／私立文系 120／私立理系 160 万（入学金は18歳の年に1回） |

仕送り・一人暮らしの費用・中学受験の塾代は**入っていない**。必要なら項目かイベントで足す。
児童手当は 2024年10月からの形（3歳未満 月1.5万／3歳〜高校生年代 月1万／第3子以降 月3万・所得制限なし）。

**すでに養育費や学費を収支の項目に入れているなら、子どもを足すと二重になる。** どちらか一方で。

## スマホに入れる

**https://todo2023.github.io/my-ai-agent/kakei/** を開くと、まずインストール画面が出る。

- **Android（Chrome）**: 「📲 アプリとして入れる」ボタンをタップ
- **iPhone（Safari）**: 画面の案内どおり、共有 → 「ホーム画面に追加」

ホーム画面のアイコンから起動したときは、この画面を挟まず `app.html` へ転送する
（manifest の `start_url` も `app.html`）。

`qr.png` はこの URL のQRコード。カメラで読めばURLを打たずに開ける。

### うまく開けない・入らないとき

**`kakei/` を最後まで付けた URL であること**を先に確認する。
`https://todo2023.github.io/my-ai-agent/` だけだと**アプリ一覧のページ**が出る（そこからでも入れる）。

それでも駄目なら **[check.html](./check.html)** を開く。
どのService Workerが担当しているか・保存が使えるか・インストールできる状態かが一覧で出る。
「キャッシュを消して読み直す」ボタンもここにある（**入れた金額には触らない**）。

## 実装メモ

- **保存は localStorage、IndexedDB ではない。** 入るのは数字と短い文字だけで、全部合わせても数キロバイト。
  画像を持つ `meshi/` とは事情が違う。同期的に読めるぶん、起動時にちらつかない
- **年齢は保存しない**（`syncPeople`）。持つと年をまたぐたびにずれる。生年だけ持ち、年齢は毎回そこから出す。
  子どもの生まれ年や項目の「いつまで」も西暦で持っているので、年をまたいで狂うところが1つもない
- **呼び名は計算側に持ち込まない。** `sim.js` は「あなた／配偶者」を既定に持ち、画面が `plan.people` で
  名前を渡す。表に出る文言（「◯◯が退職」）は名前入りになるが、計算そのものは名前を知らないまま動く
- **項目の欠けた欄は画面に出す前にうめる**（`hydrate`）。`preset.js` や書き出したJSONには
  その項目に関係のない欄が書かれていない。そのまま入力欄に流すと `value="undefined"` になる
- **グラフの下端は切ってある。** 尽きたあとの落ち込みは桁が違う（−5億など）。そこに縦軸を合わせると、
  肝心の「いつゼロを割るか」が上端の平らな線になって読めない。底は上の高さの半分まで
- **金額の入力は `type="text"` ＋ 桁区切り。** `type="number"` では区切りが出せない。
  7桁の数字を区切りなしで読み違えると、手元の表と突き合わせるという**このアプリでいちばん大事な作業**が壊れる
- **名前を打っている最中は組み直さない。** 金額やグループを変えたときだけ描き直す（指を離してから）。
  打つそばから組み直すと入力が飛ぶ
- **年の明細は開いた年のぶんだけ作る**（`breakdown`）。56年ぶんの項目別を毎回持つと、
  打つそばから計算し直す作りに耐えない。金額の出し方は `simulate` と同じ関数を通しているので、
  明細の合計とグラフの数字は必ず一致する
- **「あと月いくら」は二分探索**（`monthlyRoom`）。支出全体を一律の倍率で伸び縮みさせて、
  ぎりぎり届く額を探す。項目を1つだけ削るより「暮らしぶりを何割変えるか」の方が判断につながる。
  貯蓄の項目は動かさない（減らしても資産は減らないので、答えにならない）
- **配信を読み込んでも、カードの引落だけは残す**（`keepCardLog`）。引落の記録は、その端末で
  打った人しか持っていない（封の側は空）。まるごと置き換えると入れた月ぶんが消えるので、
  月とカードで突き合わせて、打った本人の数字を優先して混ぜる
- **カードの引落は見通しに足さない。** カードは支払いの通り道であって、あたらしい支出ではない。
  食費もレジャー費も「収支」に入っているので、足すと二重になる。記録は
  「収支表が実際とずれていないか」を確かめるためのもので、`cardLog` は `sim.js` に渡していない
- **退職の谷は隠さない。** 60歳で辞めて年金が65歳からなら、その5年は収入ゼロで出る。
  ここを均して見せる作りにはしていない。谷が見えることがこのアプリの用途そのもの
- **同居する別アプリに巻き込まれないこと。** 以前ブロック崩しがサイト直下にあり、担当範囲（scope）が
  `/my-ai-agent/` 全体だった。こちらにも保険として「別アプリの Service Worker が担当していたら、
  自前のに替わった時点で1回だけ読み直す」（`healForeignController`）を入れてある。詳しくは `meshi/README.md`
