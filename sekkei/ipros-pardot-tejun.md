# 週次でやること（IPROS → Pardot）

組み立ての全体像は [`ipros-pardot.md`](ipros-pardot.md)。こちらは**動かし始めてからの手順**。

> ⚠ **Pardotの画面のラベルは、この文書では確定させていない。**
> 見ているのは旧UI（`pi.pardot.com`）。実際に開いて確かめた名前に、あとで置き換えること。
> **推測で書いた箇所には「要確認」と付けてある。**

## 毎週の流れ（30分を目安にする）

| | どこで | やること |
| --- | --- | --- |
| 1 | IPROS管理画面 | 引き合い一覧を出す。**期間を先週分に絞る**（全期間だと2005年からの古い行が混ざり、メール無しが大量に出る） |
| 2 | Pardot（管理 → エクスポート） | 既存プロスペクトを書き出す。**メールアドレスの列だけでよい** |
| 3 | [`eigyo/lead/`](../eigyo/lead/) | 1と2を放り込んで「仕分ける」。出てきたCSVを保存 |
| 4 | 目視 | **除外**と**メール不備**の2つを開いて、巻き込み事故がないか見る |
| 5 | Pardot（管理 → インポート） | **新規インポート用**を入れる |
| 6 | Pardot（管理 → インポート） | **リスト追加のみ**を入れる。※新規作成しない設定で（要確認） |
| 7 | 営業へ | **先に営業へ回す**（`ipros_yusen_*.csv`）を渡す。ステップメールを待たない層 |

4を飛ばさないこと。**ここが人の仕事で、ほかは全部機械がやる。**

## インポートで気をつけること

- **Pardotのインポートは、メールアドレスで既存プロスペクトを突合して更新する**
  と理解しているが、版と設定で挙動が変わる。**要確認。**
  → だから最初は**5件だけのCSVを作ってテストする**。いきなり599件入れない
- 突合が効くなら「リスト追加のみ」の束は二重作成にならないはずだが、
  **効くことを確かめてから**本番の件数を入れる
- `リードソース` `動機` `至急度` は、インポート画面で**列とフィールドを手で対応づける**。
  ここを毎回そろえるため、CSVの列の順番は変えない
- **オプトアウト済みの人を上書きしない。**インポートで配信停止が解除されることは
  あってはならない（要確認。テストのときに必ず見る）

## 最初の1回だけやること

1. **`リードソース` のカスタムフィールドを用意する**（無ければ作る）
2. `動機` `至急度` のカスタムフィールドを作る（任意。あると④の分岐に使える）
3. ダイナミックリスト `IPROS_ナーチャリング対象` を作る
   （条件：`リードソース` = `IPROS` かつ オプトアウトしていない）
4. Engagement Studio に4通シリーズを載せる（Day 0 / 3 / 7 / 14）
5. スコアリングの加点ルールを確認し、必要なら9点の閾値を入れる

**1〜2が終わるまで、3〜5は作らない。**条件に使うフィールドが無い状態でリストを作ると、
あとで条件を付け替えることになって事故る。

## 送る前に必ず見ること

- **退会済み・オプトアウトが混ざっていないか。**
  `eigyo/lead/` は IPROS の「退会済み」を外すが、**Pardot側のオプトアウトは見ていない**
  （こちらからは分からないため）。**最終判断はPardot側の設定に任せる**
- 4通シリーズの本文に【要記入】が残っていないか
- テスト配信を自分宛てに1通出す

## この手順が変わるとき

- IPROS側にAPIができたら、1と3が消える（自動連携になる）
- Pardot APIに直結したら、2と5と6が消える。ただし**鍵の管理が発生する**ので、
  そのときは費用と置き場所を相談してから（[`../CLAUDE.md`](../CLAUDE.md)）
