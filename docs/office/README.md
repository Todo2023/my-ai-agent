# MTGルーム／カンファレンスルーム（デモ版）

**クライアントが開く画面。** 「AI人材派遣」の体験（スキル別・入れ替え可・月額）を、
そのまま画面にしたもの。部屋は2つある。

| | URL | 誰がいるか |
| --- | --- | --- |
| **MTGルーム** | [`index.html`](index.html) | **自社が迎えた担当だけ**。ここで仕事を渡す |
| **カンファレンスルーム** | [`conference.html`](conference.html) | **在籍者ぜんぶ**。ここで迎える担当を選ぶ |

- MTGルーム … https://todo2023.github.io/my-ai-agent/office/
- カンファレンスルーム … https://todo2023.github.io/my-ai-agent/office/conference.html

行き来は、画面上のリンクか、**部屋の下にある扉に話しかける**。
どちらの部屋も、同じ「迎えた担当」と「依頼」を見ている。
カンファレンスルームで迎えると、MTGルームにその担当が立つ。

ビルド不要・サーバーなし・外部の読み込みなし。画像ファイルもフォントも使っていない
（人も部屋も `room.js` の中で四角を積んで描いている）。

## 社内用の道具とは別もの

| | 誰が見るか | 中身 |
| --- | --- | --- |
| [`office/`](.)（ここ） | **クライアント** | 担当者の顔・できること・料金。仕事を渡す入口 |
| [`../eigyo/`](../eigyo/) | **社内** | 担当者の中身（プロンプト）。調べ方と書き方の制限 |

**この2つは意図的に分けてある。** `office/staff.js` にプロンプトを書かないこと。
クライアントに配る画面に指示文が載ると、そのままコピーして使われる。

担当を1人増やすときは、両方に足すことになる。

| | 足す先 | 何を書くか |
| --- | --- | --- |
| 見せ方 | `office/staff.js` | 役割名、肩書、経歴、できること、できないこと、料金 |
| 中身 | `../eigyo/agents.js` | 調べる先、仮説の立て方、書き方の制限 |

## 画面でできること

昔のRPGと同じ作りにしてある。**部屋を歩いて、担当に話しかける。**

1. **歩く** … 十字キー（パソコンでは矢印キー／W A S D）で1マスずつ
2. **話しかける** … 相手の正面に立って「はなす」（パソコンでは Enter か Space）。
   机は挟んでいてよい。カウンター越しに話す形
3. **扉に話しかける** … もう一方の部屋へ移る

**MTGルームで**

4. **仕事を頼む** … 会話から。商談を1件登録すると、その席に積まれる
5. **話を聞く** … プロフィール。**できないことも必ず出す**
6. **進み具合を見る** … 受付 → 準備中 → 納品済み
7. 空席には椅子だけ置いてある。話しかけるとカンファレンスルームへ案内する

**カンファレンスルームで**

8. **迎える** … 話しかけて「MTGルームに迎える」。空いている席に入る
9. **準備中の担当** … うすく描かれ、迎えられない
10. **すでに迎えた担当** … 頭にオレンジの印が付く

歩くのが難しいときのために、**「一覧で見る」**で従来のカード表示に切り替えられる。
できることは同じ。キーボードだけで操作したい場合もこちら。

## 部屋の作り

| | 何を持っているか |
| --- | --- |
| `room.js` | ドット絵、歩く動き、話しかける判定。**2つの部屋で共通** |
| `app.js` | 迎えた担当と依頼のデータ、重ねて出す画面、一覧表示。**2つの部屋で共通** |
| `staff.js` | 担当者の情報（`hello` が話しかけたときの第一声） |
| `index.html` / `conference.html` | **その部屋の形だけ**を `ROOM` に書いて渡す |

`room.js` は `OFFICE.〜` しか呼ばない。**部屋の見た目を作り直しても `app.js` は触らなくてよい。**

部屋の形は、各ページの `ROOM` を書き換える。1文字が1マス。

```
# 壁 ／ D 机 ／ P 観葉植物 ／ = 扉 ／ . 床
```

| | |
| --- | --- |
| `map` | 部屋の形 |
| `spots` | 担当が立つマス `[列, 行]` |
| `start` | 自分の初期位置 |
| `mode` | `"mtg"`（迎えた担当だけ）／ `"conference"`（在籍者ぜんぶ） |
| `door` | 扉の行き先 |

**担当を増やすと、カンファレンスルームに自動で並ぶ。** ただし `spots` の数まで。
それより増やすときは `conference.html` の `MAP` と `spots` を広げる。

## いまはデモなので、ここが本物ではない

| | いま | 本番でどうするか |
| --- | --- | --- |
| 依頼の送信 | 送信しない。端末の中に残るだけ | こちらのメール／フォームに届くようにする |
| 状態の更新 | 画面の「進める」ボタンで手動 | こちらが進める。クライアント側にボタンは出さない |
| 納品物 | 出ない | メールで送る。ここにリンクを置くかは未定 |
| ログイン | ない。誰でも開ける | 会社ごとに分ける必要がある。**要検討** |
| 席数 | 3で固定 | 契約プランに合わせる |

**「進める」ボタンは、クライアントに見せる本番では消すこと。**
いまは動きを確かめるために出してある。

### つなぐときに考えること

保存先を持つ段になったら、無料枠の範囲で組めるか先に確認する。
`hp/match/` が Supabase の無料枠を使う予定なので、そちらと同じ置き場所にできるかどうか。
ログインが必要になった時点で、無料の構成では厳しくなる可能性がある。**その前に相談する。**

**いま本当にお受けできるのは「提供中」の2人だけ。** 残りの8人は、カンファレンスルームを
それらしく見せるための枠。うすく描き、名札も点線にして、話しかけても迎えられないようにしてある。
**中身が決まるまで `state` の "準備中" を外さないこと。**

料金は仮の数字。`../hp/sales-ai/` の料金表と揃えてあるので、**片方だけ直さないこと。**
オンコロジー担当を1万円高くしてあるのは、確認の手間が増えるという想定を置いただけで、
根拠のある数字ではない。

## 経歴の書き方

`staff.js` の `career` には、**会社名・入社年・部署名を書かない。**

社名を伏せても、入社年と部署名まで揃うと人物が特定され得る。
いまは「大手製薬メーカーのオンコロジー領域で10年」まで落としてある。
`hp/README.md` の「実名について」と同じ考え方。

## ドット絵

`room.js` の `drawPerson()` が、四角を積んで人を描いている。
12×16のドットで、髪・顔・体・腕・足の順。向きと足の動きだけが変わる。
色は `staff.js` の `color` から作っている（自分だけオレンジで、担当と見分けがつくようにしてある）。

**いまの絵は仮。** 見せ方が固まったら描き直す前提。
外部の画像・フォント・3Dは読み込めない（無料構成を保つための決まり）ので、
描き直すときも、この関数の中で四角を積むか、SVG／CSSの範囲で作る。

名札だけはHTMLで置いている（`.labels`）。日本語をドットで描くと読めないため。

## パソコンで確認する場合

```bash
python3 -m http.server 8000
# → http://localhost:8000/office/            MTGルーム
# → http://localhost:8000/office/conference.html   カンファレンスルーム
```

保存した内容を消したいときは、ブラウザの開発者ツールで `localStorage` を空にする
（キーは `office.v1.seats` と `office.v1.jobs`）。
