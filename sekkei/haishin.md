# 配信のきまり（どのブランチが公開されているか）

**GitHub Pages は1ブランチしか配信できない。** このリポジトリは複数のプロジェクトが
同居しているので、**配信元を切り替えると、そのブランチに無いものは全部404になる。**
実際に2回起きている（2026-08-16 と 2026-09-01）。

## いまの配信元

| | |
| --- | --- |
| 配信元ブランチ | **`claude/hp-implementation-xubnv6`**（2026-09-01〜） |
| それ以前 | `main`（〜2026-08-31） |

**確かめかた**（推測しない。必ずこのどちらかで見る）

- リポジトリの **Settings › Pages › Build and deployment › Branch**
- **Actions** の `pages build and deployment` の一番上の実行。そこに出ている
  ブランチ名が、いま公開されているもの

## いちばん大事なこと

> **`main` にマージしただけでは、サイトには出ない。**
> 配信元が `main` でないあいだは、**配信元ブランチにも入れる**必要がある。

「直したのに変わらない」の原因は、たいていこれ。ブラウザのキャッシュを疑う前に、
**まず配信元ブランチを確かめる。**

## 404 になったときの直しかた

1. 配信元ブランチを確かめる（上）
2. そのブランチに、消えたフォルダが入っているかを見る
   `git ls-tree origin/<配信元ブランチ> --name-only`
3. 入っていなければ、**足りないものだけ**を持ってくる

```bash
git checkout -B restore-apps origin/<配信元ブランチ>
# 相手のフォルダを上書きしないよう、重なるものは除いてから
git checkout origin/main -- <足りないフォルダ…>
```

4. **相手の担当ぶんに差分が出ていないことを確かめてから**コミットする

```bash
git diff --cached --name-only origin/<配信元ブランチ> -- <相手の担当フォルダ…>
# ここが空でなければ、まだ足してはいけない
```

## `docs/` の取り合い（2026-09-01）

同じ `docs/` を2つのプロジェクトが使っていた。

| ブランチ | `docs/` の中身 |
| --- | --- |
| `main` | ふたりの体重帳（PWA） |
| `claude/hp-implementation-xubnv6` | 講座のサイト（about / lesson / pricing ほか） |

講座を動かさない方針だったので、**体重帳を `taiju/` に移した**（配信元ブランチのみ）。
中身は1文字も変えていない。すべて相対パスなので、置き場所が変わっても動く。
記録は Apps Script 側にあるので消えない。接続先URLは localStorage
（オリジン単位）なので引き継がれる。

⚠ **ホーム画面に追加していた人は、追加し直しが要る。**
古いアイコンは `docs/` を指していて、そこは講座のページになったため。

`main` のほうは `docs/` が体重帳のまま。**配信元を `main` に戻すなら、
今度は講座が消える。** どちらかに寄せるまで、この食い違いは残る。
