# IPROSリード仕分け

IPROSから出したCSVを、**Pardotに入れる前に**4つに分ける道具。

**https://todo2023.github.io/my-ai-agent/eigyo/lead/**

ビルド不要・サーバーなし・**通信なし**。選んだCSVは端末の外へ出ない。
（`fetch` も `XMLHttpRequest` も書いていない。ブラウザの開発者ツールの
ネットワークタブで確かめられる）

## なぜ要るか

岩田さんの全体フローのうち、**②「Pardot登録（重複・除外チェック）」**にあたる部分。
CSVをそのままインポートすると、

- 既にいる人がもう1件できる（プロスペクトの二重作成）
- 競合他社・代理店がナーチャリング対象に入る
- 同じ人が同じ週に2回DLしていて、2行になっている

が起きる。手作業で毎週これを見るのは無理があるので、機械にやらせる。
**判断は人が、下ごしらえは機械が**、という分け方にしてある。

## 使い方

| | |
| --- | --- |
| 1 | IPROSの管理画面から出したCSVを選ぶ（Shift_JIS でも UTF-8 でもよい） |
| 2 | Pardotの既存プロスペクト一覧のCSVを選ぶ（任意。無いと全員が「新規」になる） |
| 3 | どの列が会社名・担当者・メール・DL資料・日時かを合わせる（見出しから推測する。次回は覚える） |
| 4 | 除外する会社名を1行1社で書く |
| 5 | 「仕分ける」を押して、出てきた4つのCSVを保存する |

## 出てくるもの

| ファイル | 何 | Pardotで |
| --- | --- | --- |
| `ipros_shinki_*.csv` | 新規インポート用 | プロスペクトを新規作成してよい |
| `ipros_kizon_*.csv` | 既にいる人 | **新規作成しない。**リスト追加だけ |
| `ipros_jogai_*.csv` | 除外リストに当たった行 | **入れない。**ただし理由つきなので目視する |
| `ipros_fubi_*.csv` | メールが空・形式が不正な行 | **入れない。**IPROS側を確認する |

どのCSVにも `リードソース` 列を足して `IPROS` を入れてある。
インポート時にカスタムフィールドへ当てれば、あとの流入経路分析で効く。

## 判定の中身

- **メール** … 前後の空白を取り、小文字にして比べる。
  ドット無視やプラス以降の切り落とし**はしない**（別人を同じ人にしてしまうため）
- **会社名** … 「株式会社」「(株)」「Co., Ltd.」、空白、中黒、ハイフンを落として比べる。
  **部分一致**なので、`ニクニ` と書けば `株式会社ニクニ` も `ニクニ商事` も当たる。
  当たりすぎるので、除外の束は必ず目で見る
- **CSVの中の重複** … 同じメールが複数行あったら、**日時が新しい行**を残す。
  DL資料は「/」でつないで1行にまとめる（何を見た人か分からなくならないように）
- **日時** … 読めない書式は「古い」扱い。読める行のほうが残る

## 注意

- **出力したCSVをこのリポジトリに置かないこと。** 会社名とメールアドレスが入っている。
  `eigyo/lead/.gitignore` で `*.csv` を弾いてあるが、他の場所に置けば効かない
- 端末に残るのは**除外する会社名**と**列の対応**だけ。CSVの中身は保存していない
- このページは `noindex`。検索には出ない
