# IPROS → Pardot ナーチャリングの組み立て

岩田さんが出した全体フローを、**機械にやらせる所**と**人がPardotの画面で作る所**に
分けたもの。2026-09-10 時点の整理。元になっているのは社内_todo スレッドの投稿。

## この計画が立っている前提（2026-09-11 追記）

**「Pardotに設定できること」だけでは足りない。**正確には次の3つが揃って初めて成立する。

| | 何が要るか | どこで効くか |
| --- | --- | --- |
| 1 | **Pardot（Account Engagement）の管理権限** | ②のカスタムフィールド追加／③のダイナミックリスト作成／④のEngagement Studioプログラム作成・開始／⑤のスコアリング変更 |
| | ↑ **2026-09-11：画面を見た限り Engagement Studio・セグメンテーション・設定項目（フィールド）・インポート・エクスポート・コネクタのメニューはある。**エディションは `…us Edition`（Plus とみられる）。画面は旧UI（`pi.pardot.com`） | |
| 2 | **Salesforce側の権限とコネクタ** | ⑤の「Salesforceに通知 or タスク自動作成」。Pardot単体では完結しない |
| 3 | ~~**IPROS管理画面のログイン**~~ **→ ある（2026-09-11 確認）** | ①のCSV出力。ここだけPardotと無関係 |

**②のツール（`eigyo/lead/`）を動かすだけなら権限は要らない**が、その前後
（Pardotからプロスペクト一覧を書き出す／仕分けたCSVをインポートする）には
インポート権限を持つ人が要る。**道具は誰でも使えるが、入れる人は要る。**

### 未確認のもの

- **エディション。** Engagement Studio とダイナミックリストは、Account Engagement の
  エディション（Growth / Plus / Advanced / Premium）によって使えるかどうか・上限数が変わる。
  既にメルマガとスコアリングを運用しているなら足りている可能性が高いが、**確認が要る**
- **誰が操作するのか。** こちらにPardotのアカウントがあるのか、先方の担当者が画面を触るのか。
  後者なら、③〜⑤はこちらが書いた手順書を渡して**人にやってもらう**形になる
- **リードソースのカスタムフィールド**が既にあるか。無ければ管理者が作る必要がある

ここが崩れると、②（CSVの下ごしらえ）は残るが、③〜⑤の自動化は絵に描いた餅になる。
**3は確認できた（2026-09-11）。**残るは1と2。先に確かめるのは1のほう。
2（Salesforce側）は⑤の営業アラートだけの話なので、前半を回しはじめてからでも間に合う。

**動かし始めてからの毎週の手順は [`ipros-pardot-tejun.md`](ipros-pardot-tejun.md) に分けた。**

## 全体フロー（岩田さん案）

```
IPROS（閲覧・DL・問い合わせ発生）
 → ① データ抽出（CSV出力）
 → ② Pardot登録（重複・除外チェック）
 → ③ リスト自動追加
 → ④ Engagement Studio でステップメール自動配信（既存の4通シリーズを活用）
 → ⑤ 反応に応じたスコアリング → サンプルテストCV or 営業アラート
```

## ① データ抽出

**2026-09-07 の実物（引き合い一覧 1,156行）を見て分かったこと。**

- 出力は **CSVではなく `.xlsx`**。見出しは1行目になく、上に検索条件が十数行ならぶ
- 40列ある。`会社名` `姓` `名` `メールアドレス` `ファイル項目` `引き合い日` `引き合い時刻`
  `イプロス会員区分` のほか、`都道府県` `業種` `職種` `役職` `コメント【動機】` `コメント【至急度】`
  `興味を持ったきっかけ`（AI推定つき）まで入っている
- **`eigyo/lead/` はこの形に合わせてある**（xlsxを直接開き、見出し行を自動で探し、
  姓+名・日付+時刻をつなぐ）

### この一覧から分かった、設計に効くこと

| | |
| --- | --- |
| **メールが無い行が420/1156** | ほぼ2023年以前。2025年9月以降の414行は全件入っていた。**週次で期間を絞れば問題にならない** |
| **退会済みが31行** | 配信対象から外す必要がある。`eigyo/lead/` で自動除外している |
| **同一人物の再訪が87人・210行** | 「2回目のDL」はそれ自体がシグナル。⑤のスコアリングで加点対象にできる |
| **`コメント【動機】`** | 「具体的検討」147行／「情報収集」786行。**IPROSの時点で意向が分かる**。②でPardotに送れば、Day14を待たずに営業フォロー対象を出せる |
| **`コメント【至急度】`が「至急」** | 17行。**ステップメールに入れる前に営業へ回すべき**層 |
| **`種別`が「問い合わせ」** | 126行。ダウンロードと同じ4通シリーズに入れてよいかは要検討 |

> **提案：`動機` と `至急度` もPardotのカスタムフィールドに入れる。**
> 岩田さんの案では⑤のスコアリングはメールの開封・クリックから始まるが、
> IPROSの時点で「具体的検討／至急」が分かっているなら、**初回から差をつけられる。**
> フィールドを2つ増やすだけで、Engagement Studio の分岐にも使える。
>
> **→ 2026-09-11、ツール側は実装した。**出力CSVに `動機` `至急度` の2列が入り、
> 「先に営業へ回す」一覧（`ipros_yusen_*.csv`）が出る。実物では**599件中95件**。
> **Pardot側にフィールドを2つ作るところだけ、人の作業として残っている。**

いまはっきりしているのは「IPROS管理画面から手動出力できる」ことだけ。
**2段階でいく。**

- **当面** … 週次で手動出力（会社名・担当者・メール・DL資料・日時）
- **将来** … IPROS側にAPI/Webhookがあれば日次自動連携に切り替え

> **人がやること：IPROSサポートに「APIまたはWebhookはあるか」を問い合わせる。**
> ここが空いたままだと、件数が増えたときに手作業が積み上がる。
> 岩田さんの言うとおり、先に潰しておきたい論点。

なお、**自動連携の形になった時点で費用の話が発生する**（連携基盤・実行環境）。
[`../CLAUDE.md`](../CLAUDE.md) の第一ルールがあるので、**そこは必ず相談してから。**
手動出力＋ブラウザ内ツールの今の形は、費用ゼロで回る。

## ② 重複・除外チェック → `eigyo/lead/`

**Pardotの書き出し（10,032件・43列）と突き合わせた。2026-09-11。**

| | |
| --- | --- |
| 新規インポート用 | **276件** |
| リスト追加のみ | 236件 |
| **配信不可（オプトアウト）** | **70件** |
| 除外（退会15・競合1・代理店17） | 33件 |
| メール不備 | 420件 |

**599人のうち323人は既にPardotにいた。**CSVをそのまま入れていたら、
323件の二重プロスペクトと、**70件の「配信停止した人への再配信」**が起きていた。
②を作った理由がそのまま数字で出た形。

### Pardot側を見て分かったこと（設計が変わる）

| | |
| --- | --- |
| **`Source` フィールドは既にある** | しかも値は「**イプロス**」（カタカナ）で292件。**新しく作る必要はない。**表記もこれに合わせる（`IPROS` と書くと集計が割れる） |
| **`導入先セグメント` が既にある** | 代理店パートナー1,115件／導入済みエンドユーザー1,391件／未導入見込み客6,262件。**岩田さんの「代理店除外」は、会社名リストより確実にここで判定できる** |
| **オプトアウトが1,683件（16.8%）** | `Opted Out` 列。`Do Not Email` 列も存在するが中身は全員空。**間違えると全員が配信対象になる** |
| **カスタムフィールドが既に3つある** | `問合せ内容` `導入先セグメント` `興味のある製品（例）`。フィールドを足すやり方は確立している |
| **ダイナミックリストが既にある** | 「【FRW】ダイナミックリスト①」1,659件。③はエディション的にも実績的にも作れる |
| **メールの重複が449件** | 10,032行に対しユニークなメールは9,583。**既に二重作成が起きている。**②を通す理由の裏付け |

### ⑤の前提が崩れている

**スコアが0でない人は10,032人中250人だけ**（最高51点、9点以上は65人）。**グレードは全員空。**

岩田さんの⑤は「既存のメルマガスコアリングと同じロジックを流用」「8/24定例の9点以上を暫定流用」
という前提だが、**その既存ロジックがほぼ動いていない。**スコアリングルールを
確認して、**必要なら作るところから**になる。9点という閾値も、実績が250人分しかない状態で
決めた数字なら、運用しながら調整する前提で置くほうがよい。

CSVを入れると4つに分かれる。詳しくは [`eigyo/lead/README.md`](../eigyo/lead/README.md)。

| 束 | Pardotでの扱い |
| --- | --- |
| 新規インポート用 | プロスペクト新規作成。`リードソース=IPROS` を当てる |
| リスト追加のみ | **新規作成しない。**リストに足すだけ |
| 除外（要目視） | 入れない。競合・代理店。会社名の部分一致なので必ず目で見る |
| メール不備（要目視） | 入れない。IPROS側を確認 |

除外リストの元は、岩田さんが手動でやっていた「明らかな競合他社は除外」。
いまツールに入れているのは**ニクニ・大生工業・グローリン**の3社だけ。

> **人がやること：除外対象の正式な一覧をもらう。**3社で足りているとは思えない。

### Pardot API での直結について

Account Engagement（Pardot）にはAPIがあるが、Salesforce の Connected App の
認証情報が要る。**鍵の置き場所が新しく発生する**ので、いまは手を出さない。
手動インポートで回して、件数が問題になってから考える。

## ③ リスト自動追加

`IPROS_ナーチャリング対象` というダイナミックリストを1つ作る。条件は次のとおり。

- `リードソース` が `IPROS` である
- オプトアウトしていない
- （代理店・競合は②で弾いているので、リスト側では見ない）

②の条件を満たしたプロスペクトが入ったら、自動でここに入る。

## ④ ステップメール（Engagement Studio）

**中身はゼロから作らない。**既にある「4通シリーズ＋10ステップ電話スクリプト」を流用する。

| 配信タイミング | 内容 | 目的 |
| --- | --- | --- |
| Day 0（登録直後） | 製品紹介（FILSTAR・3つのゼロ） | 想起獲得 |
| Day 3 | 導入事例 | 信頼構築 |
| Day 7 | 技術Tips・FAQ | エンゲージメント維持 |
| Day 14 | 無料サンプルテストのご案内 | CV獲得 |

福田さんの「最初は情報発信、後半で無料サンプル測定のコンバージョンにつなげる」
という設計思想と一致している。

> **人がやること：4通シリーズの現物（件名・本文）を持ってくる。**
> 手元にないので、原稿の手直しはまだできない。
> 現物が来れば、件名の書き分けやDay14のCTA周りの推敲はこちらでできる。

## ⑤ スコアリング・営業アラート

- 各メールの**開封・クリックでPardotスコア加点**。既存のメルマガスコアリングと同じロジックを流用
- **Day14メールのクリック、またはサンプルテスト申込**があったら、
  Salesforceに通知 or タスク自動作成 → 営業フォロー
- **一定スコア以上は電話フォロー対象としてリスト化**

閾値は 8/24 定例の「**スコア9点以上**」を暫定で流用する。

> **人がやること：既存メルマガの加点ルール（開封◯点・クリック◯点）の現物確認。**
> 「同じロジックを流用」の中身が分からないと、9点が何回のクリックに当たるのかが出せない。

## 費用について

**この形なら費用はゼロ。**

- `eigyo/lead/` はブラウザの中だけで動く。サーバーもAPIキーも使わない
- 重複判定・除外判定は文字列の一致で足りる。**Claude API は使っていない**
- Pardot / Salesforce は先方が既に契約しているもの。こちらの新規課金ではない

「AIで名寄せ」「AIで競合判定」に広げると従量課金の話になる。
やるなら [`../CLAUDE.md`](../CLAUDE.md) の手順（3回確認）を踏んでから。
