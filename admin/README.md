# 審査（身内用）

投稿されたものを見て、公開するか差し戻すかを決める画面。
`biz/`（ハタラク文庫）と `ehon/`（えほんの棚）の**両方**をここで見る。

| | |
| --- | --- |
| 画面 | https://todo2023.github.io/my-ai-agent/admin/ |

**管理者（`admins` テーブルに載っているアドレス）以外には、何も表示されない。**
それはこの画面の作りではなく、データベース側の決まり（RLS）で守っている。

## なぜこの画面が要るか

子ども向け（`site = 'ehon'`）は、**人が全ページを見るまで公開しない**決まりにしてある。
しかもそれは「気をつける」ではなく、**データベースのトリガで止めてある**
（[`../supabase/community.sql`](../supabase/community.sql) の `guard_publish`）。

つまり**この画面を通す以外に、絵本が世に出る道はない。**
理由は [`../docs/platform-kids.md`](../docs/platform-kids.md) にある。

## 使い方

1. 管理者のメールアドレスでログイン（メールに届くリンクを開く方式）
2. 「審査待ち」に出ているものを開いて、中身を読む
3. **公開する** … 誰でも読める状態になる
   **差し戻す** … 理由を書く。書いた人に見える

タブで「公開ずみ」「差し戻し」も見られる。

## いまの限界（絵本）

**絵そのものはまだ送られてこない。** つくる画面は絵のファイル名だけを送る作りで、
画像の置き場所（Cloudflare R2 など）を決めていないため。

なので絵本の審査は、いまのところ次の手順になる。

1. この画面で**文とページの並び**を見る
2. **作者から絵を受け取り、中身を目で見る**
3. 問題なければ `ehon/books/（フォルダ名）/` に `book.json` と絵を置いて
   `node ehon/tools/build-index.mjs` を走らせる（これで棚に並ぶ）
4. この画面で「公開する」を押して、記録上も公開ずみにする

画面にもこの注意を出してある。**手順2を飛ばさないこと。**

記事（`biz/`）のほうは絵に依存しないので、この画面で「公開する」を押せば
そのまま一覧と記事ページに出る。

## ファイル

| | |
| --- | --- |
| `index.html` / `admin.js` | 審査の画面 |
| `admin.css` | この画面だけのスタイル |
| （接続設定） | **持っていない。`../biz/config.js` と `../biz/supa.js` を使い回している** |

同じ接続処理を3つ持つとズレるため、`biz/` のものを読み込んでいる。
この画面は PWA ではないので、フォルダをまたいでも困らない。

## つなぐときに1つだけ要る設定

Supabase の Authentication > URL Configuration > **Redirect URLs** に、この画面のURLを足す。

```
https://todo2023.github.io/my-ai-agent/admin/
```

これがないと、ログインのリンクを開いても戻ってこられない。

## 動作確認（手元）

```bash
python3 -m http.server 8000
# → http://localhost:8000/admin/
```

手元で試すときは、上の Redirect URLs に `http://localhost:8000/admin/` も足す。

## 注意

- `<meta name="robots" content="noindex, nofollow">` は**公開後も外さない**
- この画面は「読める人を制限する」作りではなく、**「読んでも何も出ない」作り**。
  URLを知られても、管理者でなければ空のまま
