# ふたりの体重帳（Google Apps Script 版）

写真を撮ると数字が入る体重記録アプリを、**すべて無料・クレジットカード登録なし**で
夫婦2人が同じURLで使える形にしたものです。

- 画面とサーバ: Google Apps Script（Googleアカウントだけで無料）
- データ: 自分のGoogleドライブのスプレッドシート（消えません）
- 写真の読み取り: Gemini API の無料枠（AI Studio のキー）

`diet_agent/`（Python + FastAPI）と同じ設計思想の、実運用向けの実装です。
カリキュラムの学習はPython版で、日々の記録はこちらで、という住み分けにしています。

## お金の話（先に）

| | 費用 | カード |
| --- | --- | --- |
| Apps Script / スプレッドシート / Googleドライブ | 0円 | 不要 |
| Gemini API（AI Studio のキー） | 0円 | 不要 |

**Gemini APIのキーに課金アカウントを紐付けないでください。** 紐付けていなければ、
無料枠を超えても請求は発生せず、`429`（混み合っています）というエラーで止まるだけです。
アプリ側もそのときは「手で入れてください」に倒れるので、記録は続けられます。

無料枠には1日あたりの回数制限がありますが、夫婦で1日1〜2枚なら桁違いに余裕があります。

> 注意: 無料枠に送ったデータは、Googleがモデルの改善に使う場合があります。
> 体重計の表示部分だけが写るように撮ってください（顔や部屋が大きく写らないように）。

## セットアップ（15分ほど）

### 1. Gemini のAPIキーを取る

<https://aistudio.google.com/apikey> で「APIキーを作成」。カード登録は不要です。
表示されたキーをコピーしておきます（あとで見返せます）。

### 2. スプレッドシートを作る

Googleドライブで新しいスプレッドシートを作り、名前を「ふたりの体重帳」などにします。
シートは空のままで構いません（必要なシートはアプリが自動で作ります）。

### 3. スクリプトを貼り付ける

1. メニューの **拡張機能 → Apps Script** を開く
2. 最初からある `コード.gs` の中身を全部消し、このフォルダの **`Code.gs`** の中身を貼り付ける
3. 左の「ファイル」の **＋ → HTML** を選び、ファイル名を **`index`** にする
   （`index.html` になります）
4. その中身を全部消し、このフォルダの **`index.html`** の中身を貼り付ける
5. 保存（フロッピーのアイコン）

### 4. キーと合言葉を設定する

Apps Script の左下 **⚙ プロジェクトの設定 → スクリプト プロパティ** で追加します。

| プロパティ | 値 | |
| --- | --- | --- |
| `GEMINI_API_KEY` | 1で取ったキー | 必須 |
| `APP_PIN` | ふたりで決めた合言葉（例: `1204`） | **推奨**。設定するとURLを知られても開けません |
| `GEMINI_MODEL` | 例: `gemini-3.6-flash` | 任意。未設定なら既定のモデル |

### 5. ウェブアプリとして公開する

右上の **デプロイ → 新しいデプロイ**、種類は **ウェブアプリ**。

- 次のユーザーとして実行: **自分**
- アクセスできるユーザー: **全員**（合言葉で守る前提。合言葉を設定しない場合は
  「Googleアカウントを持つ全員」にしてください）

初回は「このアプリはGoogleで確認されていません」と出ます。自分で作ったスクリプトなので
**詳細 → （プロジェクト名）に移動 → 許可** で進みます。

表示された **ウェブアプリのURL** が、そのままアプリのURLです。

### 6. 動作を確かめる

スプレッドシートを開き直すと **「体重帳」** メニューが出ます。
**体重帳 → セットアップを確認** で、キー・合言葉・Geminiへの接続を点検できます。

スマホでURLを開き、ブラウザの共有メニューから **ホーム画面に追加** しておくと、
アプリのように起動できます。相手にも同じURLと合言葉を渡してください。

## 使い方

1. 上のタブで「夫／妻」を選ぶ（名前はタップして書き換えられます）
2. **体重計を撮る** → 数秒で体重と体脂肪率が欄に入る
3. 数字を確かめて **この内容で記録する**

同じ日にもう一度記録すると上書きされます（朝と夜で撮り直しても二重になりません）。

## 設計の考え方

`diet_agent/README.md` と同じで、要点は2つです。

**読み取りはLLM、採否は決定的な処理。** Geminiが返した値は必ず `validate_()` を通します。

| ルール | 挙動 |
| --- | --- |
| 20〜250kg の外 | 採用せず「手で入れてください」 |
| `624` のように小数点が落ちた形 | `62.4` に直し、**直したことを画面に残す** |
| 体脂肪率が 3〜60% の外 | 体脂肪率だけ捨て、体重は残す |
| 前回から3kg以上の変化 | **値は捨てず**、読み違いの可能性として確認を促す |
| モデルの自信が0.6未満 | 確認を促す |

**保存の前に必ず人間を挟む。** `readScale` は読むだけで、シートには何も書きません。
書き込むのは、人が数字を見て「記録する」を押したときだけです。

## ロジックのテスト

判断部分（読み取り結果の検証、モデル出力の解釈）は Node で確かめられます。
Googleのサービスは呼びません。

```bash
node test_logic.js
```

## 困ったとき

| 症状 | 対処 |
| --- | --- |
| `モデル ... が使えません`（404） | Geminiのモデルは提供終了になることがあります。**体重帳 → 使えるモデルを一覧する** で確認し、`GEMINI_MODEL` を書き換えてください |
| `混み合っています`（429） | 無料枠のレート制限です。少し待つか、その回は手入力で記録してください |
| 合言葉が違います | `APP_PIN` の値と一致しているか確認。変更したら、スマホ側で一度リロードしてください |
| コードを直したのに反映されない | **デプロイ → デプロイを管理 → 編集（鉛筆）→ バージョン: 新バージョン → デプロイ** が必要です |
