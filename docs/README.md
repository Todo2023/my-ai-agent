## 1. 共通の土台

どちらも「Zennの設計」を下敷きにする。Zennを5層に分けると、共通にできる層と分ける層がはっきりする。

| 層 | 中身 | 2つで共通か |
| --- | --- | --- |
| ① 配信・インフラ | 置き場所、DB、認証、画像の配り方 | **共通** |
| ② アカウント | ログイン、プロフィール、フォロー、通知 | **共通**（子ども版は保護者アカウント。後述） |
| ③ データの骨格 | 作品、トピック、いいね、コメント、通報 | **共通**（列名まで同じにする） |
| ④ 執筆・表示 | 何をどう書き、どう読ませるか | **別**。ここが2つの正体 |
| ⑤ 運用（審査） | 何を出してよいか、いつ誰が見るか | **別**。マーケは事後、子ども向けは事前 |

**①〜③を共通にしておけば、2つ目を作るコストは半分以下になる。**
逆に④⑤を共通にしようとすると、両方とも中途半端になる。ここは分ける。

## 2. 無料枠でどこまで行けるか

数字は2026年8月時点の目安。**各社よく変わるので、使う前に必ず最新を確認する。**

| | 無料の範囲（目安） | 先に当たる壁 |
| --- | --- | --- |
| GitHub Pages | 1GB・帯域100GB/月・ビルド10回/時 | **静的しか置けない**。投稿を受け付けられない |
| Supabase 無料 | DB 500MB・帯域5GB/月・ストレージ1GB・プロジェクト2つ | **帯域5GB/月**。画像を配ると一瞬で溶ける |
| Cloudflare Pages / Workers 無料 | Workers 10万リクエスト/日 | リクエスト数。ただし帯域には強い |
| Vercel Hobby | 無料 | **商用利用が規約違反。有料販売をするなら使えない** |

**帯域5GB/月が、どちらのサービスでも最初に来る壁。**
何回読まれたら尽きるかは、1回あたりの重さで決まる。

| | 1回の重さ | 5GBで何回 |
| --- | --- | --- |
| マーケ記事（文章＋画像2枚） | 約 300KB | **月 約1.7万回** |
| 絵本1冊（20ページ・最適化後） | 約 3MB | **月 約1,600回** |

**同じ無料枠でも、絵本は10倍早く尽きる。** ここが2つの一番大きな違い。
対策は各ファイルに書いた。

## 3. 段階と、止まって相談する線

| | やること | 費用 |
| --- | --- | --- |
| **Phase 0** | 中身をリポジトリに置いて GitHub Pages で配る。作るのは身内だけ。投稿は受け付けない | **ゼロ円** |
| **Phase 1** | ログイン・投稿・反応を Supabase 無料枠で足す。招待制 | **ゼロ円** |
| ⚠️ **相談ライン** | 独自ドメイン／Supabase有料／画像配信／検索エンジン | ここから有料 |
| **Phase 2** | 一般公開、検索、通知メール | 月 数千円〜 |
| **Phase 3** | 有料販売・投げ銭 | 決済手数料＋事務 |

**Phase 1 までは、いまの決まり（`../CLAUDE.md`）の範囲で作れる。**
Phase 2 に入る操作は「相談なしにやってはいけないこと」にそのまま当たるので、手前で必ず止まる。

ただし、**現構成の方針とは1点ぶつかる。**

> 現構成：「ビルドなし。HTML / CSS / JS をそのまま置く」「外部の読み込みなし」

Phase 1 以降はこれを満たせない。エディタ・Markdown変換・ログインが必要で、素のHTMLだけでは無理がある。
**費用の話ではないが、方針変更の判断が要る。** Phase 0 のあいだは現方針のまま作れる。

## 4. お金について、いま確認したいこと

`../CLAUDE.md` の決まりに沿って先に挙げる。**どれもまだ着手していない。**

1. **ドメイン** … `todo2023.github.io/...` の下で始めるか、独自ドメインを取るか（年1,500円〜）。
   コミュニティは後からURLを変えると検索での積み上げを失うので、**判断は早いほうがよい**
2. **2つを1つのSupabaseに同居させるか** … 無料プランはプロジェクト2つまで。
   分けると枠を使い切る。同居させればDBは1つで済むが、片方の障害が両方に出る
3. **Supabase有料への切り替え時期** … 無料枠を超えたら止めるのか、$25/月へ上げるのか
4. **画像の置き場所**（特に子ども版） … Supabase Storage は帯域が弱い。
   Cloudflare R2 は転送量無料だが**カード登録が要る場合がある**。無料の範囲かどうか要確認
5. **決済**（Phase 3） … Stripe の手数料は決済ごと（国内カードで3.6%前後）。
   加えて**特定商取引法の表記・インボイス・返金対応**が必要。機能より事務のほうが重い
6. **Claude API を使うか** … 使うなら `hp/match/` と同じ歯止め
   （手動実行・件数上限・`max_tokens` 明示・usage記録・事前の費用提示）を必ず入れる。
   **Phase 0/1 では使わない前提**

## 5. 共通のデータ設計

2つで**列名まで同じにする**部分。`hp/match/` と同じく、読み取りは RLS で止める。

| テーブル | 中身 |
| --- | --- |
| `users` | Supabase Auth（メールのリンク方式。パスワードを持たない） |
| `profiles` | 表示名・自己紹介・リンク |
| `works` | 作品（記事／絵本）。`slug` `title` `topics[]` `status` `published_at` |
| `topics` | トピック。マスタを持って表記ゆれを防ぐ |
| `likes` `comments` `follows` | 反応 |
| `notifications` | 通知 |
| `reports` | 通報。**あとから足すと過去分に対応できない。最初から持つ** |
| `products` `purchases` | 販売・購入 … **後日（要相談）** |

`works.status` は `draft` / `review`（審査待ち）/ `published` / `rejected` の4つ。
マーケ版は `review` を素通ししてよいが、**子ども版は `review` を人が通さないと公開しない**。
状態を共通にしておけば、運用の厳しさだけを切り替えられる。

**下書き（`draft`）が anonキーで読めてしまう事故が一番怖い。**
公開前チェックの必須項目にする。
