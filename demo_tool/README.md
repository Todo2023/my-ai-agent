# デモ体験ツール

入力された曖昧な問いを、意思決定に直結する鋭い問いに書き換えて返します。
9月21日のデモで、各自が好きな時間にアクセスして体験するためのものです。

- 画面: `docs/demo.html`（GitHub Pages から配信）
- サーバ: `worker.js`（Cloudflare Workers）

## なぜこの構成か

GitHub Pages は静的ファイルしか置けないため、**APIキーを隠す場所がありません**。
ブラウザに書けば誰でも読めてしまいます。そこで、鍵を持つ処理だけを Cloudflare Workers に置きます。

| | 選んだもの | 理由 |
| --- | --- | --- |
| AI | **Gemini API の無料枠** | Claude API は従量課金で無料枠が無い。お支払い情報を登録していないため課金は発生しない |
| サーバ | **Cloudflare Workers** | 無料枠は1日10万リクエスト。Netlify は 2026-08-18 にビルド枠切れで公開が止まった前例がある |
| 保存 | **Cloudflare KV** | Supabase の無料プロジェクトは7日間無操作で一時停止する。デモ当日に止まる事故を避けた |

## 設計の切り分け

CLAUDE.md の設計ルールに従っています。

- **LLM がやるのは、問いの書き換えとその説明だけ。**
- **合否の判定はコードが行う**（`worker.js` の `check`）。金額・「必ず」「保証」などの約束・
  個人名が混ざった出力は、画面に出す前に落とします。一度表示された文言は取り消せないためです。
- 検査に落ちたら1回だけ作り直させ、それでも駄目なら「うまく書き換えられませんでした」と正直に返します。

試験は `node test_worker.mjs` で走ります（**19件**／ネットワークもGeminiも使いません）。
Geminiへの通信を差し替えて、返ってきた内容ごとに何が起きるかを確かめています。
「2回とも検査に落ちた場合、落とした内容が画面に漏れないこと」もここで見ています。

## 無料枠と、止まる可能性

Gemini の無料枠には **1分あたり**と**1日あたり**の上限があります。超えると 429 が返ります。
**デモ当日は同時アクセスが重なるため、ここが一番止まりやすい場所です。**

そのため 429 は異常ではなく想定内として扱い、画面には
「いま混み合っています。**20秒ほど**待ってから、もう一度送ってください」と出します。黙って失敗させません。

アクセスコードで人数を絞れるので、配る枚数で負荷を調整できます。

## スマホから配信する（PCが無いとき）

**`wrangler deploy` はPCのターミナルでしか打てません。** スマホしか無い日に
直したものが反映できず止まる、ということが起きます。

そのために、**GitHub の画面から押すだけで配信できるボタン**を用意してあります。

### 使いかた（毎回）

1. GitHub でリポジトリを開く → **Actions** タブ
2. 左の一覧から **「Worker を配信する」** を選ぶ
3. 右の **Run workflow** を押す → もう一度 **Run workflow**
4. 緑のチェックが付けば配信できています（1〜2分）

**「試すだけ（配信しない）」にチェックを入れると、配信せずに中身だけ確かめます。**

出す前に自動でテスト（`test_worker.mjs`）が走り、**落ちたら配信しません。**
配信のあと、外から Worker を叩いて**本当に動いているか**まで確かめます。

### 最初の1回だけ：鍵を2つ登録する（スマホでできます）

**① Cloudflare で API トークンを作る**

1. https://dash.cloudflare.com/profile/api-tokens を開く
2. **Create Token** → テンプレートの **Edit Cloudflare Workers** を選ぶ
3. Account は自分のアカウント、Zone は **All zones** のままで進む
4. **Create Token** → 出てきた文字列をコピー
   **この画面を離れると二度と見られません。** 先にコピーしてください
5. **この文字列は誰にも見せないこと。**チャットにも貼らないでください

**② Account ID を控える**

Cloudflare の Workers の画面、右側に出ている **Account ID** をコピーします。

**③ GitHub に登録する**

1. リポジトリの **Settings** → **Secrets and variables** → **Actions**
2. **New repository secret** を2回押して、次の2つを登録

| 名前 | 中身 |
| --- | --- |
| `CLOUDFLARE_API_TOKEN` | ①でコピーした文字列 |
| `CLOUDFLARE_ACCOUNT_ID` | ②でコピーした ID |

**名前は1文字も違えないでください。**違うと「鍵が登録されていません」で止まります
（止まるだけで、壊れません）。

### 気をつけること

- **すでに登録してある secret は消えません。** `GEMINI_API_KEY`・`ACCESS_CODES`・
  `ASK_ADMIN_KEY`・`SLACK_WEBHOOK_URL`・`CALENDAR_TOKEN` はそのまま残ります
- 配信するのは**配信元のブランチ**（`claude/hp-implementation-xubnv6`）の中身です。
  **PRをマージしてから**押してください
- **ボタンを押したときだけ動きます。**定期実行は付けていません
  （`../CLAUDE.md` の「自動実行・定期実行を作らない」に従っています）

### お金

**ゼロです。** 公開リポジトリの Actions は無料で時間の上限もなく、
Cloudflare の API トークンにも料金はかかりません。

## デプロイ手順（PCがあるとき）

Cloudflare のアカウントが要ります（無料）。

### 1. wrangler を入れる

```
npm install -g wrangler
wrangler login
```

### 2. 利用回数とログの置き場所を作る

```
wrangler kv namespace create DEMO_KV
```

表示された `id` を `wrangler.toml` の該当箇所に貼ります。

### 3. 鍵とアクセスコードを登録する

**この2つは `wrangler.toml` に書かないでください。** GitHub に入ってしまいます。

```
wrangler secret put GEMINI_API_KEY
```

続けて、アクセスコードを登録します。JSON を1行で貼ります。

```
wrangler secret put ACCESS_CODES
```

貼る内容の例（コードは推測されにくい文字列にする）:

```json
{"TODO-G1-HHVA3":{"audience":"student","max_uses":null},"TODO-G2-NDN4R":{"audience":"student","max_uses":null},"TODO-G3-7VVGU":{"audience":"student","max_uses":null},"TODO-G4-9LMVJ":{"audience":"student","max_uses":null},"TODO-PR-4DHTL":{"audience":"pro","max_uses":null}}
```

**学年ごとに1本ずつ、計5本**です。どの学年から使われたかが利用ログで分かります。
`max_uses` は `null`（無制限）。デモの目的は体験してもらうことなので、途中で止めません。

コードは見間違えやすい文字（`0` `O` `1` `I` `S` `5` `B` `8`）を避けて作ってあります。
口頭やスクリーンショットで伝えても取り違えにくくするためです。

`max_uses` を `null` にすると無制限、`3` にすると3回までです。
**あとから `wrangler secret put ACCESS_CODES` をやり直すだけで変えられます。**

### 4. 公開する

```
wrangler deploy
```

表示された URL（`https://todo-demo-tool.〇〇.workers.dev`）を、
`docs/demo.html` の `API_URL` に貼ります。

### 5. 動作を確かめる

PowerShell では次のように打ちます（`〇〇` は自分のURLに置き換える）。

```
curl.exe -X POST https://todo-demo-tool.〇〇.workers.dev -H "Content-Type: application/json" -d '{\"code\":\"TODO-G1-HHVA3\",\"audience\":\"student\",\"text\":\"AIって結局何に使えるんですか\"}'
```

書き換えた問いと説明が返れば成功です。

## 資料ページからの質問を Slack で受け取る

受講者が `lesson-NN.html` のスライドの下から質問を送ると、**その質問と「どのスライドを見ていたか」がSlackに届きます。**

### 1. Slack で受け口を作る

1. https://api.slack.com/apps を開き、**Create New App → From scratch**
2. 名前は「講座の質問」など。ワークスペースは自分のものを選ぶ
3. 左の **Incoming Webhooks** を開き、スイッチを **On**
4. **Add New Webhook to Workspace** → 質問を流したいチャンネルを選ぶ
5. 出てきた `https://hooks.slack.com/services/...` をコピーする

無料プランで使えます。

### 2. Worker に登録する

```
wrangler secret put SLACK_WEBHOOK_URL
```

貼り付けて Enter。続けて、溜まった質問を後から読むための合鍵も入れておきます（好きな文字列で構いません）。

```
wrangler secret put ASK_ADMIN_KEY
```

```
wrangler deploy
```

### 3. 動作を確かめる

```
curl.exe -X POST https://todo-demo-tool.〇〇.workers.dev/ask -H "Content-Type: application/json" -d '{\"lesson\":\"第1回\",\"slide\":\"3\",\"name\":\"テスト\",\"text\":\"届いていますか\"}'
```

Slackに出れば成功です。

### ワークと質問で、届け先を分ける

ワークの提出と質問が同じチャンネルに混ざると、どちらも読み飛ばされます。
**ワーク用のチャンネルをもう1つ作って**、そのWebhookを登録してください。

1. Slackで、ワーク提出用のチャンネル（例：`#work`）を作る
2. さきほどのアプリの **Incoming Webhooks** → **Add New Webhook to Workspace** → そのチャンネルを選ぶ
3. 出てきたURLを登録する

```
wrangler secret put SLACK_WORK_WEBHOOK_URL --name todo-demo-tool
```

| 何が | どこに届くか |
| --- | --- |
| スライドからの質問 | `SLACK_WEBHOOK_URL` のチャンネル |
| ワークの提出 | `SLACK_WORK_WEBHOOK_URL` のチャンネル |

**`SLACK_WORK_WEBHOOK_URL` を登録しなければ、ワークも質問側に届きます。**
分けるまでの間も、黙って消えることはありません。

### みんなの質問

資料ページの右側に、**同じ回に寄せられた質問**が出ます。**名前は出しません。**
自分に開いていない回の質問は返しません（本文と同じ扱いです）。

見せたくない質問が出たときは、取り下げられます。`id` は資料ページの
右側に出ている質問のもので、`GET /ask?key=…` でも確認できます。

```
Invoke-RestMethod -Uri "https://todo-demo-tool.〇〇.workers.dev/question/hide?key=（合鍵）" -Method Post -ContentType "application/json" -Body '{\"id\":\"q:lesson-01:1234567890\"}'
```

**受講者どうしに見えるものなので、投稿された質問はそのまま出ます。**
不適切なものが出たときに気づけるよう、質問はSlackにも同時に届きます。

### Slack が使えないときも、質問は消えません

質問は**Slackに送る前にKVへ保存**しています。Slackが未設定でも、落ちていても、質問そのものは残ります。読むときは合鍵をつけてブラウザで開いてください。

```
https://todo-demo-tool.〇〇.workers.dev/ask?key=（ASK_ADMIN_KEYに入れた文字列）
```

直近100件が新しい順に出ます。保存期間は180日です。

### 迷惑投稿への備え

- 人には見えない空欄を1つ置いてあり、そこが埋まっていれば機械とみなして捨てます
- 同じ回線からは1時間に10件まで
- 600文字まで

資料ページ自体にパスワードがかかっていますが、**この入り口自体は誰でも叩けます**（静的サイトのため隠せません）。上の3つは、荒らしを減らすためのもので、完全に防ぐものではありません。

## 教材の配信と、提出で次が開く仕組み

教材の本文とスライドは、**非公開リポジトリ `Todo2023/todo-curriculum`** にあります。
公開サイトには置きません（置くと、パスワードをかけてもURLを知る人には読めるため）。

`todo-curriculum` で `uv run upload.py` を実行すると、本文とスライドがKVに載ります。
受講者が資料ページを開くと、この Worker が**その人に開いている回だけ**を返します。

### 開く条件

次の**小さいほう**まで開きます。

1. 提出した回 ＋ 1
2. `paidThrough`（支払いで解放された回まで）

デモと「はじめに」は提出を求めません。開き方の詳しい説明と、受講者の登録方法は
`todo-curriculum/README.md` にあります。

### 入り口

| 道 | 何を返すか |
| --- | --- |
| `POST /me` | 一覧と、どの回が開いているか。**本文は返さない** |
| `POST /lesson` | その回の本文。開いていなければ 403 |
| `GET /slide` | スライド画像1枚。開いていなければ 403 |
| `POST /submit` | ワークの提出。次の回が開く |
| `POST /member?key=…` | 受講者の登録・支払い範囲の更新（合鍵が要る） |

**画像も本文と同じ鍵で守っています。**画像だけ抜かれては意味がないためです。

## 商談用のコードを1つ作っておく

法人の打ち合わせで、その場で体験ツールを触ってもらうためのコードです。
**受講者ごとのコードとは別に、使い回せるものを1つ用意しておきます。**

```
Invoke-RestMethod -Uri "https://todo-demo-tool.todo-inc-2023-10-13.workers.dev/member?key=$KEY" -Method Post -ContentType "application/json" -Body '{"code":"TODO-DEMO","name":"shodan","paidThrough":1,"audience":"pro"}'
```

`$KEY` は `ASK_ADMIN_KEY` に登録した合鍵です。PowerShell を開き直したときは、
先に `$KEY = "（合鍵）"` を実行してください。

**`paidThrough` を 1 にしているのは意図です。** デモと「はじめに」までしか開かないので、
商談相手に本編の教材が渡ることはありません。体験ツールは問題なく使えます。

打ち合わせでお渡しするリンク：

```
https://todo2023.github.io/my-ai-agent/demo.html?audience=pro&code=TODO-DEMO
```

## オフィスアワー（予約制＋在席表示）

**基本は予約制です。**枠をこちらで登録し、受講者が1つ押さえます。
そのうえで、いま話せるときだけ在席を立てると、資料ページに「いま話せます」が出ます。
**在席は約束にしていません。**出せるときだけ出す、という扱いです。

### 準備（一度だけ）

面談の入り口になるURLを登録します。Google Meet の無料枠で作れます。

```
"https://meet.google.com/xxx-xxxx-xxx" | wrangler secret put OFFICE_URL --name todo-demo-tool
```

**このURLは、予約した本人と、在席中のときだけ受講者に見えます。**
予約していない人には返しません。

### 枠を登録する

PowerShell で、`$k` に合鍵（`ASK_ADMIN_KEY`）を入れてから。

```powershell
$k = "合鍵"
$u = "https://todo-demo-tool.todo-inc-2023-10-13.workers.dev/oh/admin?key=$k"
```

| やること | 送るもの |
| --- | --- |
| 枠を足す | `'{"op":"add","at":"2026-09-10T20:00+09:00","dur":30}'` |
| 枠を消す | `'{"op":"remove","id":"202609101100"}'` |
| 一覧を見る | `'{"op":"list"}'` |
| いま話せます を出す | `'{"op":"open"}'` |
| いま話せます を消す | `'{"op":"close"}'` |

```powershell
Invoke-RestMethod -Method Post -Uri $u -ContentType "application/json" -Body '{"op":"add","at":"2026-09-10T20:00+09:00","dur":30}'
```

- **日時は `+09:00` を付けてください。**付けないと世界標準時として扱われ、9時間ずれます
- 同じ日時をもう一度足しても、増えません（同じ枠として上書きされます）
- **予約が入っている枠は、そのままでは消せません。**どうしても消すときは `"force":true` を足します。
  そのときは、予約した人に必ず連絡してください

### 決めていること

| | なぜ |
| --- | --- |
| 1人が同時に持てる予約は1つ | 押さえたまま来ない枠が積み重なると、他の人が取れなくなる |
| 取り消せるのは自分の予約だけ | 他人の枠を空けられては困る |
| 他の人の名前と相談内容は返さない | 埋まっていることしか分からない |
| 過ぎた枠は一覧に出さない | ただし自分が予約したものは、記録として残る |

予約と取り消しは、**ワーク用のSlackチャンネル**に流れます。

### 枠が無いとどうなるか

受講者には「いま出ている枠はありません」と出ます。**予約できないだけで、画面は壊れません。**
ただ、枠を出していない状態が続くと、質問欄しか使われなくなります。
**週に1〜2枠は出しておくことをおすすめします。**

## 質問に答える（Slack → 教材）

受講者が資料ページから送った質問は、Slackに流れます。その本文に

```
`ask:1756800000000`  ← 回答するときはこの番号
```

という番号が入っています。**この番号を使って、答えを教材の側に戻します。**

### 答え方

<https://todo2023.github.io/my-ai-agent/answer.html> を開き、合鍵（`ASK_ADMIN_KEY`）を入れます。
未回答の質問が上から並ぶので、上から順に書いて「答えを戻す」を押すだけです。

書いた答えは、**同じ回を開いている受講者の「みんなの質問」に並びます。**
質問と同じく、**お名前は出ません。**

- 合鍵はブラウザに保存しません。閉じると消えます。端末を共有していても安全なためです
- 回が分からない質問（デモからの質問など）は、答えても受講者の画面には出ず、控えだけに残ります
- 書き直しはいつでもできます。同じ番号に上書きされます

### なぜSlackから直接返せないのか

Slackに送るのに使っている Incoming Webhook は**送る専用**で、返信を読み取れません。
読み取るには Slack app を作り、Events API を設定する必要があります（無料枠で可能）。
そこまでやらなくても、上の画面で用は足りるので、いまはこの形にしています。

Slackから直接返せるようにする場合は、次が必要です。

1. Slack app を作り、`app_mentions` または `message.channels` を購読する
2. Worker に受け口（`/slack/events`）を足し、署名の検証を入れる
3. 本文から `ask:...` の番号を拾って `/answer` と同じ処理を呼ぶ

**署名の検証を省いてはいけません。**URLを知られると、誰でも回答を書けてしまいます。

## 無料枠を止めないための決まり

**上限に当たって機能が止まることは、絶対に避けます。**

### Cloudflare KV の枠（1日あたり）

| | 上限 | 何が使うか |
| --- | --- | --- |
| 読み出し | 100,000回 | 資料を開く、スライドを見る、質問を読む |
| **書き込み・削除・一覧（合計）** | **1,000回** | 教材を載せる、提出、質問、予約 |

**細いのは下の1,000回のほうです。**ここが詰まると、提出も予約もできなくなります。

### 受講者が触る経路では、一覧（list）を使わない

一覧は1,000回の枠を使います。資料を開くたびに呼んでいると、
**人が増えたときに、いちばん細い枠から先に詰まります。**

そこで、受講者が開く画面（みんなの質問・オフィスアワー）は、
**「どれがあるか」の索引を1つ読んでから中身を読む**形にしてあります。
読み出しは100,000回あるので、そちらに寄せるほうが安全です。

この決まりは**試験で固定してあります**（`test_worker.mjs` の「無料枠を守る」）。
受講者の画面から `list` を呼ぶ実装に戻すと、試験が落ちます。

### 1人が資料を1回開くと、どれだけ使うか

| 操作 | 読み出し | 書き込み等 |
| --- | --- | --- |
| 資料を1回開く（スライド30枚込み） | 約33回 | 0回 |
| ワークを1本出す | 数回 | 2回 |
| 質問を1件送る | 数回 | 4回 |
| オフィスアワーを予約する | 数回 | 1回 |

**受講者10人が毎日1回ずつ資料を開いても、読み出し330回・書き込み0回**です。
書き込みを使うのは、こちらが教材を載せるときと、受講者が何かを出すときだけです。

### 教材を載せるとき

`upload.py` は**変わったものだけ**載せます（1枚直せば書き込み1回）。
全部載せ直す `--all` は408回使うので、**1日に2回までです。**
800回を超えそうなら警告し、1,000回を超える見込みなら**実行前に止まります。**

### 上限に近づいたら

Cloudflareから90%で通知が来ます。**課金はしません。**
その日は `--all` を使わず、翌日の 00:00 UTC（日本時間9:00）のリセットを待ちます。

## 予約をGoogleカレンダーに入れる

2段構えです。**1は設定なしで動いています。**2は一度だけ設定が要ります。

### 1. Slackの「カレンダーに追加」リンク（設定不要・すでに動いています）

予約が入ると、Slackの通知に **▶ カレンダーに追加** というリンクが出ます。
押すとGoogleカレンダーの登録画面が開き、日時・題名・場所が入った状態になります。
保存を押すだけです。

### 2. 自動でカレンダーに入れる（一度だけ設定）

受け口を Google Apps Script で作ります。**無料枠だけで動きます。**

**手順**

1. <https://script.google.com/> を開き、「新しいプロジェクト」
2. `demo_tool/calendar/gas.js` の中身を、まるごと貼り付ける
3. 先頭の `TOKEN` を、自分で決めた合言葉に書き換える（推測されにくいもの）
4. 右上「デプロイ」→「新しいデプロイ」→ 種類は **ウェブアプリ**
   - 次のユーザーとして実行： **自分**
   - アクセスできるユーザー： **全員**
   - ※「全員」でないと Worker から呼べません。合言葉で守っています
5. 初回は許可を求められます。カレンダーへのアクセスを許可してください
6. 表示された **ウェブアプリのURL**（`https://script.google.com/macros/s/…/exec`）を控える

**Worker側に登録する**

```
"控えたURL" | wrangler secret put CALENDAR_HOOK_URL --name todo-demo-tool
"決めた合言葉" | wrangler secret put CALENDAR_TOKEN --name todo-demo-tool
```

これで、予約が入ると**自動でカレンダーに予定が入り**、取り消されると**自動で消えます。**

**設定できたか確かめる**

```
curl -X POST "https://todo-demo-tool.todo-inc-2023-10-13.workers.dev/oh/admin?key=運営の鍵" -d "{\"op\":\"caltest\"}"
```

1時間後に「テスト：カレンダー連携の確認」という15分の予定が入れば、通っています。
入らないときは、返ってくる `reason` が場所を教えます（未設定／届かない／受け口が401など）。
KVには何も書かないので、何度試しても無料枠は減りません。確認用の予定は手で消してください。

### 止まらないようにしていること

- **受け口が未設定でも、落ちていても、予約そのものは成立します。**
  カレンダーに入らなかったときは、Slackに「カレンダーは手で消してください」と出ます
- 二重に入らないよう、追加の前に同じ予約が無いかを見ています
- 取り消しは、追加のときに付けた印（予約の番号）で探します。
  題名で探すと、同じ名前の予定を巻き込むためです

### 使う枠

Apps Script の無料枠は、**1日あたりの実行回数と実行時間**で決まっています。
予約1件につき1回なので、**1日に数十件でも桁が2つ足りません。**
カレンダー側の書き込みも同様です。ここが上限に触れる心配はありません。

## 提出物の一覧（運営用）

<https://todo2023.github.io/my-ai-agent/works.html>

Slackに流れるだけだと、**誰がどこまで出したか**が分かりません。この画面で見ます。

| 見えるもの | |
| --- | --- |
| 受講者ごとの進み | 何回出し終えたか、最後の提出から何日空いたか、未返信が何件か |
| 提出物 | 新しい順。頭だけを出し、押すと全文が出ます |

- **未返信が多い人が先に並びます。**次に、間が空いている人
- 名前を押すと、その人のぶんだけに絞れます
- **添削そのものはSlackで返します。**この画面で付けるのは「返した」という印だけです
- 合鍵はブラウザに保存しません

### なぜ「間が空いた日数」を出すか

**止まった人ほど、そのまま戻ってきません。**提出が無いと次の回が開かない作りなので、
1回止まると、そこで終わります。日数が伸びている人に一声かけるためのものです。

### 枠のこと

この画面は**運営しか開かない**ので、一覧（list）を使っています。
1回開くと数回ぶん使いますが、1日に何十回開いても問題ない範囲です。
**受講者が触る画面では一覧を使いません。**
