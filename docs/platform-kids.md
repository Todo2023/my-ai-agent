# 子ども向けの本・絵本のプラットフォーム（設計メモ）

絵本・児童書を投稿して、読んでもらえて、いずれ売ったり応援したりできる場所。
マーケ版（[`platform-marketing.md`](platform-marketing.md)）と同じ土台の上に載せる。まだ何も作っていない。

インフラ・費用・段階は [`README.md`](README.md) に共通で書いてある。ここは中身の話。

## 1. 結論

| 問い | 答え |
| --- | --- |
| 投稿して読める場所を作れるか | **作れる** |
| Zennと同じ設計でよいか | **土台は同じでよい。書く／読む／審査は別物になる** |
| 「Markdownで手軽に」が成り立つか | **絵本では成り立たない**（後述）。文章もの（童話・児童書）なら成り立つ |
| 無料で作れるか | **作れる。ただしマーケ版より10倍早く無料枠が尽きる** |
| 一番の障害は何か | **技術ではない。「公開前に人が全部見る」という運用コスト** |

**マーケ版より難しい。** 難しさの中身が技術ではないところが厄介で、
作ってから気づくと引き返せないので、先に書いておく。

## 2. Markdownが主役にならない

Zennの設計を持ってきたときに、最初に壊れるのがここ。

| | Zenn / マーケ版 | 絵本 |
| --- | --- | --- |
| 主役 | 文章 | **絵** |
| 単位 | 1本の記事（縦に長い） | **1ページ／見開き**（横に並ぶ） |
| 文字量 | 数千字 | 1ページ 0〜40字 |
| 読み方 | スクロール | **めくる** |
| 必要なもの | 記法 | **絵の配置とページ送り** |

なので、**2種類を分けて設計する。**

| 種類 | 書き方 | Markdown |
| --- | --- | --- |
| **絵本** | ページごとに「画像1枚＋短い文」を並べるエディタ | 使わない（文の部分だけ） |
| **童話・児童書（文章もの）** | 章ごとに文章。挿絵は任意 | **そのまま使える** |

「Markdownで手軽に」が効くのは後者。**文章ものから作るほうが、圧倒的に早く形になる。**
絵本エディタは後回しにできる。

絵本のデータは、記事1本＝1レコードではなく**ページの配列**で持つ。

| テーブル／列 | 中身 |
| --- | --- |
| `works.kind` | `ehon`（絵本）/ `story`（文章もの） |
| `works.age_min` `works.age_max` | 対象年齢（0-2 / 3-5 / 6-8 / 9-12 のような区分） |
| `works.reading_minutes` | 読み聞かせの目安時間。**親が選ぶときの一番の判断材料** |
| `pages` | `work_id` `page_no` `image_path` `text` `ruby`（ふりがな） `alt` |
| `works.body_md` | 文章ものの本文（絵本では使わない） |

**ふりがな（ルビ）を最初から列で持つ。** あとから足すと全作品の入力し直しになる。
`<ruby>` タグを本文に埋めるのではなく、別に持って**表示時にオン／オフを切り替えられる**ようにする
（4歳と9歳で必要なものが違う）。

読む側は **PWA にする**。このリポジトリの得意分野で、しかも**帯域対策として効く**（後述）。
`../README.md` の決まりどおり、専用フォルダを切る（例：`ehon/`）。scope を重ねない。

## 3. 子ども向けで根本から変わる4点

### (1) 審査が「事後」から「事前」になる

**ここが最大の設計変更で、最大のコスト。**

Zennやマーケ版は、公開してから問題があれば消す（事後）。読み手が大人だから成り立つ。
**子どもが読む場所で、未審査の投稿をそのまま出すことはできない。**

つまり `works.status` の `review`（審査待ち）を、**人が必ず通す**。

| | |
| --- | --- |
| 1冊あたり | 絵20ページを目で見て数分 |
| 月100冊 | 数時間 |
| 月1,000冊 | **1人では回らない** |

**これが規模の上限を決める。**サーバー代ではなく、見る人の時間が先に尽きる。
国内に子ども向けUGCの成功例が少ないのは、だいたいこれが理由。

現実的な手当て。

1. **招待制で始める**。書き手を選べば審査は軽い
2. **Claude API で一次スクリーニング**（暴力・性的・差別・宗教勧誘・広告誘導を検出）→ **最終判断は人**
3. AIを通した／通さないに関わらず、**公開されたものは全部人が見た状態にする**

2について、概算は次のとおり。**やる前に費用を出して確認する**（`../CLAUDE.md` の決まり）。

| | |
| --- | --- |
| 画像20枚 ＋ 文 | 入力 約3万トークン／冊 |
| Haiku 4.5（入力 $1/1M） | **約 5円／冊** |
| Opus 5（入力 $5/1M） | 約 23円／冊 |

月100冊なら Haiku で500円程度。単価は変わるので**使う前に最新を確認する。**

### (2) 子どものアカウントを作らない

**子どものアカウントを作らなければ、規制の面倒の大半が消える。**

2026年の個人情報保護法改正で、**子どもの個人情報の取得には法定代理人の関与を義務付ける**方向で
制度が動いている（従来もガイドライン上、おおむね12〜15歳以下は法定代理人の同意が必要とされてきた）。
**いままさに変わっている最中の分野**なので、実装前に最新を確認する必要がある。

これを踏まえた設計。

| | |
| --- | --- |
| アカウントを持つ人 | **保護者と、作り手（大人）だけ** |
| 子ども | アカウントなし。保護者の端末で読む。**「こどもプロフィール」は端末の中だけに置く**（年齢・名前をサーバーに送らない） |
| 読書履歴 | 端末内（PWAのローカル保存）。サーバーに個人単位で貯めない |
| 学校で使われる場合 | 個人情報を集めない作りなら、そのまま使える |

**「集めない」が一番安く、一番安全で、一番速い。**
おすすめ機能の精度は落ちるが、その代償は割に合う。

### (3) コメント欄をZennと同じにしない

大人向けのコメント欄をそのまま子どもの場所に置くのは危険（見知らぬ大人と子どもが直接つながる）。

| | |
| --- | --- |
| 自由記述のコメント | **作り手 ↔ 保護者アカウントのみ**。子どもは書かない |
| 子どもができること | 定型のリアクション（「すき」「もういっかい」など数種の固定ボタン）だけ |
| DM | **作らない** |
| プロフィール | 子どもの写真・実名・地域を載せられないようにする（入力欄自体を作らない） |

### (4) 決済は保護者に限定される（Phase 3）

- **未成年者が単独でした契約は取り消せる**（民法。返金請求が通る）
- なので**購入・投げ銭は保護者アカウントでのみ可能**にする。子どもの画面に購入ボタンを出さない
- スマホアプリとしてストア配信するなら、Google Play のファミリー向けポリシーや
  Apple のキッズカテゴリの制限（広告・外部リンク・第三者解析）が乗る。
  **PWAで配れば、この制約を丸ごと避けられる**（これもPWAで始める理由）

## 4. 無料枠は絵で死ぬ

**絵本は1冊が重い。ここがマーケ版との一番大きな実務上の違い。**

| | |
| --- | --- |
| 1ページ（WebP・長辺1600px） | 約 150KB |
| 1冊（20ページ） | **約 3MB** |
| Supabase 無料の帯域 5GB/月 | **月 約1,600冊ぶん。1日50回読まれたら終わり** |
| Supabase 無料のストレージ 1GB | **約300冊で満杯** |

そのままでは**開いた初月に止まる。** 対策は3つあって、どれも無料。

1. **画像は GitHub Pages から配る**（帯域100GB/月）。
   Phase 0（身内が作った絵本を置く）なら、画像をリポジトリに入れるだけで**月3万冊ぶん**になる。
   Supabaseは反応と管理だけに使う
2. **PWAでキャッシュする**。一度読んだ絵本は端末に残る。
   **繰り返し読む**のが絵本の性質なので、これが一番効く。既存アプリと同じ作り方でできる
3. **投稿時に必ず縮小・WebP化**して、元画像は残さない。長辺1600pxで足りる

Phase 1（投稿を受け付ける）に進むと1が使えなくなるので、
**画像の置き場所（Cloudflare R2 など、転送量無料のもの）を決める必要がある。
R2はカード登録が要る場合があるので、そこは相談ライン。**

## 5. マーケ版との違い（まとめ）

| | マーケ版 | 子ども版 |
| --- | --- | --- |
| 書き手 | 社会人 | 作り手（大人） |
| 読み手 | 社会人 | **子ども＋保護者** |
| 主役 | 文章 | **絵** |
| Markdown | 保存形式として使う | 文章ものだけ。絵本では使わない |
| 審査 | **事後** | **事前（人が必ず見る）** |
| アカウント | 本人 | **保護者のみ。子どもは持たない** |
| コメント | 自由 | 大人同士だけ。子どもは定型リアクション |
| 無料枠の壁 | 月1.7万PV | **月1,600冊。10倍きつい** |
| 一番のコスト | スパム対策 | **審査の人手** |
| 決済（Phase 3） | 本人 | **保護者のみ**（未成年者取消） |

## 6. どちらから作るか

**マーケ版を先に作って、土台を子ども版に流用するのがよい。**

- 共通部分（[`README.md`](README.md#1-共通の土台) の①〜③）はマーケ版で先に固まる
- マーケ版は事後審査で回るので、**運用の人手なしで公開まで行ける**
- 子ども版は事前審査が要るので、**公開の前に「誰がいつ見るか」を決めないと開けない**

子ども版だけ先に作ると、作り終えてから審査体制で止まる。順番はここで効く。

## 7. まだ決まっていないこと

- 作り手は誰を想定するか（プロの作家／親／子ども自身／保育士・先生）。
  **子ども自身に描かせる**なら、投稿者側も未成年になり、規制が投稿側にも乗る（難易度が上がる）
- 読み上げ（TTS）を入れるか。端末の音声合成なら無料。録音音声を載せるなら容量が跳ねる
- 対象年齢の区切り方
- 「読み放題」の形にするか、1冊ずつ買う形にするか（Phase 3の話）
