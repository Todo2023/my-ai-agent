エージェント動作仕様ビューア

3つのエージェントが1回の指示をどう処理するかを、ステップ単位で追える画面。どこをLLMが判断し、どこを決定的なコードが固め、どこで人間の承認が入るかを色で区別している。

    この画面の読み方

    • LLM判断（橙）のステップだけがモデルへの呼び出し。ここがレイテンシとコストのほぼ全てを占める。invoice_agent は1リクエスト1回に固定されている。
    • 固定処理（青）は決定的なPythonコード。表記ゆれの吸収・計算・PDF生成・ユーザーに見せる文面の組み立ては全てこちら側。LLMが嘘の完了報告をしても、画面に出る文言はコードが作った事実だけになる。
    • 人間の承認（赤）は不可逆な操作の直前に必ず置く。LangGraph の interrupt、CLIの [y/N] がその実装。ここを迂回する変更は入れない。
    • travel_agent に承認ゲートが無いのは、外部への副作用が読み取り専用の検索だけだから。承認ゲートの有無は、副作用が不可逆かどうかで決まる。

    出典：invoice_agent/graph_agent.py、meeting_agent/agent.py・cli.py、travel_agent/agent.py・search.py。数値は invoice_agent/gate4_findings.md（評価データセット22件・モデル gemma-4-26b-a4b-it）の実測値。トレースの文面は、実装のプロンプト・分岐・出力テンプレートから再現したもので、実行のたびに変わる箇所がある。
