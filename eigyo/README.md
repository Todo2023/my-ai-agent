# 営業AIの作業台

営業支援AI（商談準備代行）を実際に回すための道具。
プロンプトを毎回書き直さなくていいように、入力欄を埋めるだけで同じ品質の指示が出るようにしてある。

**https://todo2023.github.io/my-ai-agent/eigyo/**

ビルド不要・サーバーなし・通信なし。スマホのブラウザで開いて、そのまま使える。
入力した内容は端末の中（localStorage）にだけ残る。

## 3つの工程

| | 何をするか | いつ使うか |
| --- | --- | --- |
| **商談準備** | 相手企業を調べ、提案書ドラフトと商談準備メモを作る | 納品物を作るとき（毎週） |
| **ターゲット** | 補助金の採択企業一覧から、条件に合う会社を表にする | 新しい営業先を仕込むとき |
| **メール下書き** | 1社ぶんのメール文面を3案作る | 送る直前 |

どれも「プロンプトを作る」→「コピーする」→ AIに貼る、という流れ。
**AIの出力をそのまま納品・送信しない**のが前提の作りになっている。

## 使い方

1. ページを開く（ホーム画面に追加しておくと早い）
2. 上のタブで工程を選ぶ
3. 入力を埋める。※必須の欄が空だと作れない
4. 「プロンプトを作る」→「コピーする」
5. Claude などの入力欄に貼って実行する
6. **出てきたものを人が確認してから使う**

入力は工程ごとに自動で保存される。「こちらが売るもの」のように毎回同じことを書く欄は、
1回入れれば次から入ったままになる。消したいときは「入力を消す」。

## 週の回し方（定期常駐型）

| | やること |
| --- | --- |
| **月曜 午前** | クライアントから翌週の商談予定を受け取る（企業名・商談日・会う人・目的） |
| **月曜 午後** | 「商談準備」を1件ずつ回す。出力をそのまま保存 |
| **火曜 午前** | 出典URLを開いて事実確認。推測と事実の切り分けを直す。商談で使えない部分を書き直す |
| **火曜 午後** | 納品（企業リサーチ／提案書ドラフト／商談準備メモの3点） |

確認にかかる時間が、このサービスの原価のほとんど。
1件あたりどれくらいかかるかを最初の数件で測っておくと、料金プランの妥当性が判断できる。

## ターゲットの元データ

「新規事業に着手しそうな会社」を勘で探すと外れる。
**補助金の採択企業一覧を起点にする。** 新しいことをやると社内で決めて、書類まで出した会社だけが載っている。

### 使う情報源

| | 何が取れるか |
| --- | --- |
| **各補助金の採択者一覧** | 採択された企業名と事業計画名。公式サイトにPDF/Excelで載る。ものづくり補助金・新事業進出補助金・事業再構築補助金など |
| **中小企業庁 成長加速マッチングサービス（ミラサポコネクト）**<br>https://mirasapo-connect.go.jp/ | 同じ採択情報を検索できる形にしたもの |
| **gBizINFO**<br>https://info.gbiz.go.jp/ | 経済産業省の法人情報オープンデータ。法人番号・所在地・従業員数・資本金・業種・補助金の採択情報。**規模で絞るのはここが速い**。REST APIもある（要トークン申請） |
| **企業の公式サイト** | 会社概要（従業員数）と、役員一覧・あいさつページ（意思決定者の役職） |

補助金に採択されると、**法人番号・法人名・都道府県・市区町村・事業計画名・補助金名・申請年度・採択結果**が
公表される。根拠は中小企業庁の「関連事業データ利活用ポリシー」
（https://www.chusho.meti.go.jp/hojyokin/data_policy/ ）。

いちばん効くのは **事業計画名**。「その会社がこれから何を始めるか」がそのまま書いてある。
これがメール本文の書き出しになる。

### 気をつけること

- **事業計画名は公表されている表記のまま扱う。** 要約も言い換えもしない。
  メールで引用するので、正確さがそのまま品質になる
- **採択されたこと自体を売り込みの材料にしない。** 「ご採択おめでとうございます」から入るメールは、
  補助金の営業と同じ見え方になる。触れるのは事業計画の中身のほう
- ミラサポコネクトには、支援機関としてデータ開示依頼を出し、企業の承認を得て詳細情報を見る仕組みがある。
  **そこで得た情報を、この用途（一方的な営業メール）に使わない。** 公表されている一覧の範囲で足りる
- 会員登録やログインが要るページからは取らない。robots や利用規約に反する取り方もしない
- 採択企業だからといって、こちらの商材に合うとは限らない。規模と事業内容は必ず別に確認する

### 業種の傾向

事業再構築補助金の採択は、製造業がいちばん多い。次いで卸売・小売業、建設業。
**設備投資を伴う業種が採択されやすい**という傾向は、複数の回で共通している。

> ⚠️ 具体的な割合は数字が割れている。CLAUDE.md には「13次：製造業43.6%／卸売・小売13.3%／建設12.8%」とあるが、
> 第13回公募の結果を紹介している複数の記事では「製造業33.8%／卸売・小売14.4%／建設14.2%」となっている。
> 応募ベースと採択ベースの違い、あるいは回の取り違えの可能性がある。
> 数字を対外的に使う前に、事務局の公式PDF（`jigyou-saikouchiku.go.jp` の公募結果概要）で確認すること。
> **絞り込みの方針（製造業を厚めに見る）は、どちらの数字でも変わらない。**

## アウトバウンドの回し方

```
採択企業一覧 ─→ ターゲット（AI）→ 人が1社ずつ見て絞る ─→ メール下書き（AI）→ 人が読んで直す → 人が送信
  gBizINFO ─┘                          ↑ 確度Cを落とす            ↑ 事実は渡すだけ      ↑ 全自動にはしない
```

- 「ターゲット」の出力は、確度A・Bだけ残す。Cは基本的に捨てる
- 従業員数と事業計画名は、出典URLを開いて確認する。AIは規模を間違えるし、計画名も要約したがる
- ターゲット表の「事業計画名」列を、そのまま「メール下書き」の同じ欄に貼る。ここで打ち直さない
- 「メール下書き」には、確認済みの事実だけを材料として渡す。
  ここでAIに調べさせない（調べさせると、確認していない情報が本文に混ざる）

### メールを送る前に

広告・宣伝を含むメールには、特定電子メール法にもとづく表示が必要になる。
プロンプトには次の4つを署名に入れるよう書いてあるが、**送信前に必ず自分の目で確認すること。**

- [ ] 送信者の名称・氏名
- [ ] 送信者の住所
- [ ] 苦情・問い合わせの受付先（メールアドレスまたは電話番号）
- [ ] 配信停止（受信拒否）の通知先と、その方法を書いた一文
- [ ] 【要記入】が残っていないか
- [ ] 送信元アドレスや件名を偽っていないか

一度「送らないでほしい」と言われた相手には、以後送らない。断られた企業を記録しておく仕組みが要る。

> この節は法的助言ではない。実際の運用を始める前に、条文か専門家で確認すること。
> 総務省・消費者庁の資料（特定電子メールの送信の適正化等に関する法律）が一次情報。

## 実行コストのこと

**このツール自体は無料だが、AIの実行には費用がかかる。**

- 設計・検証のあいだは、個人向けプラン（Claude Pro など）の範囲で足りる
- **クライアント向けに実行するときは、APIキー経由の従量課金に切り替える。**
  個人向けの Max / Pro プランは、第三者に提供するサービスの実行には規約上使えない
- 商談準備1件あたりのAPI費用を実測して、料金表（月4件4万円／月8件8万円）に織り込む

料金ページには「料金にAIの実行費用を含む」と書いてあるので、
1件あたりの原価が想定を超えていないかは、月次で見ておく。

## 文面を直したいとき

プロンプトの本文は **`prompts.js` だけ** に入っている。
`index.html` にも `app.js` にも日本語のプロンプトは書いていないので、直すのはこの1ファイル。

```js
{
  id: "shodan",          // 保存に使う名前。変えると入力の保存が消える
  name: "商談準備",       // タブに出る名前
  sub: "…",
  lead: "…",             // 画面の上に出る説明
  fields: [ … ],         // 入力欄
  build: function (v) {  // ここが組み立て。ただの文字列の足し算
    return [ "…", "…" ].join("\n");
  }
}
```

入力欄を1つ増やすなら `fields` に足して、`build` の中で `v.新しい名前` と書く。

```js
{ k: "budget", label: "想定予算", ph: "例）年間300万円まで" }
```

`type` の書き方。

| 書き方 | 出るもの |
| --- | --- |
| 省略 | 1行の入力欄 |
| `type: "area"` | 大きい入力欄（複数行） |
| `type: "date"` | 日付の選択 |
| `type: ["A", "B"]` | 選択肢（プルダウン） |

`req: true` を付けると必須になる。
