# LINEへの誘導のしかた（設計）

2026-09-03 作成。**まだ作っていません。**進めてよいかを決めるための紙です。

## 先に、いちばん大事なところ

**LINE公式アカウントの無料枠は「月200通」です。**しかもこれは
**「配信1回」ではなく「届いた人数ぶん」**を数えます。

> 友だちが100人いるときに一斉配信を1回すると、**100通**。
> 月に2回で使い切ります。3回目は**送れません**（無料プランは追加購入もできません）。

友だちが増えるほど、送れる回数が減ります。**放っておくと必ず止まります。**
CLAUDE.md の「上限に触れて機能が止まるのは、課金と同じくらい駄目」に真正面から当たります。

### だから、この設計の骨は1つ

**押されたら返す（応答メッセージ）だけで組み立てる。こちらから送る（配信）は、原則しない。**

| 種類 | 通数を使うか | この設計での扱い |
| --- | --- | --- |
| あいさつメッセージ（友だち追加の直後） | **使わない** | ここに全部載せる |
| 応答メッセージ（相手が言葉を送ったら返す） | **使わない** | 主役。何人来ても無料 |
| リッチメニュー（下に出るボタン） | 使わない | 主役。ここから全部たどれる |
| チャット（1対1の手動返信） | **使わない** | 質問はここで受ける |
| 一斉配信・ステップ配信 | **使う（人数ぶん）** | **原則しない。**使うのは下の1回だけ |

この形なら、**友だちが1,000人になっても費用も上限も動きません。**

## 何のために誘導するのか

いまの導線は、X →（お問い合わせ or イベント案内）→ **メール**です。
メールは、学生にとって重い。開かない、返さない、迷惑メールに入る。

LINEを挟む目的は1つだけです。

> **体験ツールのリンクを、その場で受け取れるようにする。**

いまは「メールを送る → 私が読む → 返す」で最短でも数時間かかります。
LINEなら**友だち追加した瞬間**に渡せます（あいさつメッセージ。通数を使いません）。

## 導線

```
X の投稿
  └→ contact.html / event.html
        └→「LINEで受け取る」ボタン（＋QRコード）
              └→ 友だち追加
                    └→ あいさつメッセージ（無料・無制限）
                          ├ 体験ツールのリンク
                          ├ 使い方3行
                          └ リッチメニュー
                                ├「体験ツールを開く」→ 応答メッセージでリンク
                                ├「講座について」  → イベント案内ページへ
                                ├「質問する」      → チャットで受ける
                                └「社会人と話したい」→ 応答メッセージで申込フォーム
```

**押した人にだけ返す。**だから何人来ても無料です。

## 段どり（3つに割る）

### 第1段：友だち追加と、あいさつだけ（半日）

- LINE公式アカウントを作る（無料。審査なし）
- あいさつメッセージに、体験リンクと使い方を書く
- `event.html` `contact.html` に「LINEで受け取る」ボタンとQRを置く
- **配信はしない**

これだけで、いまのメール往復が消えます。**費用ゼロ、上限に触れません。**

### 第2段：リッチメニューと応答メッセージ（半日）

- 下のボタン4つを置く
- 「体験」「講座」「質問」「社会人」の言葉に反応して返す
- **ここまで、通数はいっさい使いません**

### 第3段：配信を、1回だけ使う（判断が要ります）

デモ最終日の前日など、**本当に伝えたい1回**にだけ使います。

- 友だち100人なら100通。**月200通の半分**
- 送る前に、友だち数 ×  回数を数えてから決める
- **月2回を超える運用は、無料では成立しません。**そうしたくなったら、
  配信ではなく「リッチメニューを差し替える」（無料）で代える

## 数えておくこと

| 何 | いくつ | 上限 | 危ないか |
| --- | --- | --- | --- |
| 友だち追加 | 何人でも | なし | — |
| あいさつメッセージ | 追加のたび1通 | **数えない** | — |
| 応答メッセージ | 押されるたび | **数えない** | — |
| リッチメニュー | 何度でも差し替え可 | なし | — |
| 一斉配信 | 友だち数 ×  回数 | **月200通** | **ここだけ** |

**受講者が1人増えると増えるのは「配信したときの1通」だけです。**
配信しない限り、何人増えても0です。

## やらないこと（決めておく）

- **Messaging API での自動送信**をしない。プログラムから送ると、
  数え間違いで上限に当たる。押されたら返す形なら、その事故が起きない
- **ステップ配信**（追加から◯日後に自動で送る）をしない。同じ理由
- **Claude API をつないで自動応答させる**をしない。CLAUDE.md の
  「自動実行・定期実行を作らない」に当たる。質問は人が読んで返す
- **有料プランへの変更**をしない。上限に当たりそうになったら、
  送るのをやめるほうを選ぶ

## 個人情報のこと

LINEで友だちになると、**表示名とアイコンがこちらから見えます。**
いまの `privacy.html` はメールとSlackの前提で書いてあるので、
**LINEを始めるなら、先に1段落足す必要があります。**

- 何が見えるか（表示名・アイコン・送られたメッセージ）
- 何に使うか（ご案内と、質問への回答だけ）
- 消し方（ブロックすれば届かなくなる。会話の記録の消し方も書く）

**これを書く前に公開しないでください。**

## 決めていただきたいこと

1. **第1段だけ先に作りますか。**（半日・費用ゼロ・上限に触れません）
2. アカウント名は「合同会社Todo」でよいですか。講座名にしますか
3. 第3段（配信）は、**デモ期間中に1回だけ**という縛りでよいですか

1を「進める」と言っていただければ、
`event.html` と `contact.html` のボタン、あいさつメッセージの文案、
`privacy.html` の追記まで、こちらで用意します。
**LINE側の登録操作だけは、Todoさんにお願いすることになります。**
